## P129: `merge_train.py add` prints ADDED for a PR the drain then drops as ALREADY (S6-V50)
Verdict: ACCEPT -> R10-TRAIN-OVERLAP-GRADE (queued; owns `merge_train.py`, where P112 already carries the spool edits `add --front` and `add --remove`; no PR or handoff ref, at origin/main da12aa37d and at the roster branch). The fix makes `add` and the drain share one admission rule.

Read at da12aa37d, the two disagree by construction. `train_add` (`merge_train.py:787` onward) answers ALREADY only for a PR in `QUEUE_PENDING`, which holds the batches still to run, or in the spool (806-809); otherwise it spools the entry and prints ADDED (817-819). The drain, `queue_take` (2356 onward), drops any PR in `seen` (2367-2370), and `batch` seeds `seen` with every PR the train ever held (2317), including the ones it skipped. `skip` (2286-2296) records the PR, phase and reason, not the head.
Cost: S. One predicate in `merge_train.py` used by both `train_add` and `queue_take`: a PR is a duplicate when it is still to run in this train or already spooled, or when this train merged it, or when it entered this train at the same verdict head. A PR skipped at one head and added at a new verdict head is admitted, and both sides say so. The `seen` set becomes a map from PR to the verdict head it entered at, with a merged mark. Self-test arms as below. The benefit is a critical-path PR that is no longer silently left out of a live train, which today only a person reading the log catches.
Binding: an ADDED that the drain then drops is a false report on the merge path, and the train is the one instrument on that path. The cost is one predicate in a file the group already owns. Re-admission at the same head is refused, so a skipped PR is not retried with nothing changed. A merged PR stays refused, so nothing runs twice.
