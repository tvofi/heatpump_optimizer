## P123: carry a verdict across a mechanical head move that does not touch the PR's own change (S6-V47, owner-raised and widened)
Verdict: ACCEPT narrowed -> R10-TRAIN-OVERLAP-GRADE (queued; owns `merge_train.py`, the train's guards and its `--approval-carry`; no PR or handoff ref). The widened allowlist is narrowed in three places to close the safety holes listed under Binding.
Source: s6 `proposals.md` `## V47` and its widening by tvofi, 2026-10-25: the carry should apply to every mechanical head move that does not affect the code.
Instances: 2 observed, #2807 and #2813 (the filing's figures), each a full re-review for the text of the PR's own delivery row. Read at this base: `merge_train.py` `--approval-carry` (line 189 onward: "answers a cost measured three times") re-posts an owner approval only across a clean recarry; the train refuses a car whose "newest posted verdict is not verdict/<N>'s tip"; and `app_push.sh --row-only` accepts only a row add (`row_only_verdict`, lines 198-235), not an edit. R10-FLY-ROW-HEAD-CARRY carries CI results across a row-only head, not a review verdict, and is held behind R10-FLOW-MQ-PROBE; the two do not overlap and can ship independently.
Cost: S: one predicate shared by `merge_train.py` and the bus verdict-head check: carry the verdict from h0 to h when the PR's own three-dot patch is byte-identical at both once the allowlist paths are removed; a carry line naming h0, h and the excluded paths, posted as `--approval-carry` does; self-tests with a positive arm per class and a negative arm each for one code line, one test line, a conflict resolution and a budget value. It also changes what a verdict is valid for, so `dev/governance/roles/fix-review.md` ("a head that moved under the review is a blocked verdict") and the matching `orchestrator.md` clause change in the same PR; that is policy, which the owner raised and the mandate approves at merge. The saving is a full re-review on every PR whose only later change is mechanical.
Binding: an owner-raised ACCEPT unless a safety hole exists; four exist in the wording as filed and the ruling closes each. (1) "Bot autofix commits (closures.json, claim files, nightly kill records)": `closures.json` decides which scripts the scoped gate runs and a claim file records an accepted value drift, so carrying across them would carry a verdict across a change of gate scope or a new claim. Narrowed: a claim file only by pure deletion of lines (dropping an inherited claim; any added or changed line refuses as a claim-value change), `closures.json` only in a commit authored and committed as `github-actions[bot]` (the rule `pr-contract` already applies to autofix repairs), and a changed budget value always refuses. (2) "Written by a known instrument" must be checkable: the path allowlist plus the commit identity is the check, because a path list alone is spoofable by any author. (3) "State docs" and "line-number re-pins in the body" are not paths; the allowlist names `dev/programme/delivery/<N>.md` and the generated state-docs files by exact path, and a body edit never moves a head. (4) A clean recarry can change behaviour through main (a semantic merge); the verdict already carries across one under `--approval-carry`, the CI at the new head still runs, and the overlap grade (this group's other carry) grades the merge tree, so the carry adds no new exposure. A code-owned path in the diff always refuses, since `tvofi`'s review attaches to the code-owned file, not to the verdict.
Carry text (for `roster_edit.py append-carry R10-TRAIN-OVERLAP-GRADE`, citing `triage: dev/programme/triage/s6-batch25.md#P123`): "Carry a verdict across a mechanical head move. A verdict at h0 is valid at h when the PR's own three-dot patch (`git diff $(git merge-base origin/main h)...h`) is byte-identical to the one at h0 (`...h0`) once only these are excluded: (a) the PR's own `dev/programme/delivery/<N>.md`, added or edited; (b) a clean merge of main (no conflict hunk in any file the PR changes); (c) a commit authored and committed as `github-actions[bot]` that changes only `tests/closures.json`, claim files by pure line deletion, or nightly kill records; (d) the generated state-docs files, by exact path. Post a carry line naming h0, h and the excluded paths as `--approval-carry` does; `app_push.sh --row-only` accepts a row edit as well as a row add. Share the predicate between `merge_train.py` and `bus.sh`'s verdict-head check, and change `dev/governance/roles/fix-review.md` and the matching `orchestrator.md` clause in the same PR (policy; owner-raised under mandate 6329234399).
