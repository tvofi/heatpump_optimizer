## P64: opener seat's worktree holds the branch update_pr.sh needs (S6-V10)
Verdict: ACCEPT narrowed -> R10-FLY-OPENPR-ATOMIC (owns app_push.sh and its openers); carry: each instrument that pushes a PR branch from a worktree it keeps detaches that worktree once, after the last push of its run, when the worktree is clean (no untracked file) and HEAD equals the pushed sha; any later run that pushes from the same worktree re-attaches it first. Never inside app_push.sh.
Source: s6 proposals.md S6-V10. Proposed `update_pr.sh --free-holders` rejected. Re-cut twice after the 2738 fix reviews (blocked, ruling-unsound): the first wording detached inside app_push.sh; the second missed handoff_push.sh's update arm, which reuses the detached worktree.

The refusal is update_pr.sh's `checked out elsewhere` exit (`git show origin/main:tools/audit/seat/update_pr.sh | grep -n 'checked out elsewhere'`).
Cost: S -- one shared helper in `pr_args.sh` (which all three sites source; clean with no untracked file and HEAD equals the pushed sha, then `git checkout -q --detach`), called at four sites, one re-attach in handoff_push.sh's update arm, and a self-test arm per site plus one for update-after-open.
Binding: the detach cannot live in app_push.sh, and it must survive the worktree's next run. `open_pr.sh` pushes once to open the PR (p1, its `$D/p1.log` push), commits its delivery row in the same worktree (`commit_row`), then pushes again (p2, `$D/p2.log`); handoff_push.sh's open arm does the same (`mut:push-open`, `commit_row`, `mut:push-row`). A detach after p1 puts the row commit on a detached HEAD, and app_push.sh's committed-tip gate (`grep -n 'is not the committed tip' tools/pr/app_push.sh`) refuses a HEAD that is not `refs/heads/$br`. So the detach is after the run's last push. The next run is the second constraint: handoff_push.sh's update arm (the `gh pr view "$BR"` branch ending at `mut:push-update`) reuses the same `$WT` and runs `git reset -q --hard "origin/$BR"`, which on a detached worktree moves only HEAD, so its merges and `ensure_row` commit land off `refs/heads/$BR` and the same gate refuses (fix review 2738 round 2, `origin/review/2738:evidence/repro_update_after_detach.txt`). That arm therefore re-attaches first, `git -C "$WT" checkout -q -B "$BR" "origin/$BR"` in place of the reset; a re-attach refused because another worktree holds `$BR` is the existing loud refusal, not lost work. This re-attach is owed even without the detach: merge_train.py `--free-holders` (`free_holder`) can already detach that worktree today.
Sites, by the rule `git grep -nE 'bash "?\$_push"?|push_app [0-9]' -- tools ':!tools/pr/app_push.sh'`, which returns eight lines; each is dispositioned:

Its `$WT` is a sibling of the main checkout, outside `$HPO_STATE_DIR/pr/`, so update_pr.sh's sweep does not reach it; this site removes the class for handoff openers. Next run: the update arm, which re-attaches (Binding); a refused earlier attempt with no PR removes the worktree and re-adds it with `-b`, which a detached worktree does not affect.

Its worktree lies under `$HPO_STATE_DIR/pr/`, which update_pr.sh's sweep (the `OWN=` loop) already detaches when clean and origin-contained, so this site adds little; it is named for symmetry. Its `upd-<branch>` worktree is re-added with `-B` on `$BR` each run and stays on the branch afterwards, so between runs it holds `$BR` against any other `worktree add` of the branch (merge_train.py's recarry stops on it as `HOLDER`). Next run: update_pr.sh removes `$WT` (`worktree remove --force`) and re-adds it with `-B`, which a detached worktree does not affect.
- `remerge_main.sh` (`--recarry`): pushes an existing PR and opens none; not a site. merge_train.py's recarry goes through it and is likewise not a site.
- Not a code path: a seat that calls `app_push.sh` by hand to open a PR (as the triage seat does) detaches its own worktree after the PR and its row are pushed; that is a step in the opener's brief.
Why not `update_pr.sh --free-holders`: not because detaching a worktree outside `$HPO_STATE_DIR/pr/` is unsafe. merge_train.py's `freeable` already detaches any holder, with no prefix restriction, when `status --porcelain` is empty (an untracked file counts as a claim) and HEAD equals `origin/<br>`; under that predicate the files stay, the branch ref stays at a sha origin holds, and `git -C <holder> switch <br>` restores it. A seat still using such a worktree loses nothing; its next commit lands on a detached HEAD and app_push.sh's committed-tip gate refuses its push, loudly. The first wording of this section said otherwise, and that was overstated. The reason is placement: a `--free-holders` flag on update_pr.sh would be a second consumer-side copy of merge_train.py's flag, needed again by each further consumer, while a detach at the instrument that made the holder removes the holder for every consumer at once. The helper's predicate is `freeable`'s (empty porcelain, HEAD equals the pushed sha), stricter than the sweep's ancestor test, so a holder the helper leaves is one `freeable` would also refuse. Null control: a worktree with an untracked file, or HEAD ahead of the pushed sha, stays on its branch. Mutants: the clean condition, the HEAD-equals-pushed condition, and the update arm's re-attach (the update-after-open self-test arm fails without it), one each.
