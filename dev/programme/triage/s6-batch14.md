## P83: a cloud pool run ends its turn while a background job is pending (S6-V18)
Verdict: REJECT (the prompt change, candidate (a), and the idle-time reclaim, candidate (b)); the idle-versus-ended instrument is DEFERRED
Source: s6 `proposals.md` `## V18`. Re-ruled before merge on the orchestrator's correction (2026-10-24, about 18:3xZ): the first ruling at fe155d28, ACCEPT NARROWED to a new group R10-FLY-CLOUD-WAIT, rested on the premise that a cloud run whose turn ends behind a background job is never resumed, and the run log refutes that premise.
Instances: 0 lost jobs. The orchestrator read the run log (RemoteTrigger `get_run_log`, run cse_01SeVeYCKsQwZTCi9e1C7Vv4, the #2745 reviewer at f7aab34f). Its turn ended at 17:53:51Z with a job pending; at 18:12:02Z a new `init` delivered that job's task notification, and the run read the output and continued the review. It re-inited again at 18:17, 18:20, 18:24 and 18:27, once per Monitor event. A cloud run is therefore resumed by its own background-task notifications, so the setup line in `_prompt` (`tools/audit/seat/cloud_dispatch.py`) is correct as it stands. The real cost was 1 duplicate reviewer (cse_01F1Ff) on the same review: the sweep read `worker_status` idle (between turns) as ended and refired. The #2750 instance is not yet re-checked against its run log, so it counts as unconfirmed, not as a second case.
Cost: (a) about 2 lines in a hot renderer, cutting off behaviour that works, so it would buy nothing and cost something. (b) as in P55: an idle reclaim races a live run, and this instance is exactly that race, because a run idle between turns for 18 minutes was alive. The deferred instrument is a reader that tells idle-between-turns from ended, from the run log's last `result` line and whether a Monitor or background task is still live. It needs RemoteTrigger run-log calls, which only the main session can make (subagents lack RemoteTrigger), so it would be one more API call per idle run in each sweep plus a parser for a log format the tree does not pin yet.
Binding: the premise is false, so (a) has no benefit at all. For the instrument, one confirmed misread (one duplicate reviewer cycle) against a new reader of an unpinned log format is not "clearly"; an unmeasured benefit is DEFER, never ACCEPT. What would change the answer: the #2750 run log re-checked and showing the same misread, or any further duplicate refire caused by reading `worker_status` idle as ended. Then re-rule the instrument as a sweep-side check that refires only on a run whose log's last line is a `result` with no live Monitor or background task. Until then the refire step reads the run log before refiring; that is the orchestrator's own step, not a carry.
