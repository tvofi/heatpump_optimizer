# RCA-2028: `root-cause-unanswered` again, and the red-history arm that never ran in CI

The root-cause seat for issue **#2028** ("[policy] recurring friction:
root-cause-unanswered"), filed by the governance cron's friction step after
#1985's RCA (`R9-RCA-1985.md`) disposed the same key one day earlier. It runs
beside no fix (`dev/governance/roles/root-cause.md`).

- Base measured: `origin/main` at `4647321d` (2026-10-08).
- Evidence: `dev/audit/rca/2028/`. Every figure names its file and command
  (section 7).

**Trigger.** Recurrence of a friction key. It is process friction, not a
`bugclasses.json` class, so no class barrier is owed (`defect-root-cause.md`).

The brief's hypothesis, "the fixer writes `## Red checks` before CI settles",
is true and is the reason A and B exist: the body is written before the head it
describes has run anything. But for A and B the cheaper detector already
exists and fires — `pr-contract` re-graded at the head by
`pr-contract-rerun.yml` (D13-s1-03) — and in A it fired first. #1985 measured
the same shape (11 of 17 refused before the verdict).

**Class D is new, and it is a defect.** Every one of the 35 `pr-contract` logs
at these heads prints

    skip     red-history           neither GITHUB_TOKEN nor GH_TOKEN is set, ...

The arm (`redHistoryForHead`, #1144, a07dd57d, 2026-09-19) reads the check runs
of every branch commit through the API and skips without a credential. The
step that runs it, "Check the body against the contract", has never carried
one: its `env:` held `PR_TITLE` and `PR_HEAD` at a07dd57d (then in
`governance.yml`), at b6e30297 (the move to `pr-contract.yml`), at f88438dd and
at `origin/main`. So for nineteen days the check printed an honest `skip` and
went green on exactly the bodies it exists to refuse. Its self-test drives the
pure function with fixture runs, which is why nothing noticed.

commit on top of 3362e0f0, whose `closures` failed at 08:27:17Z). Program:

| `GH_TOKEN` set | `record ... 6 commit(s) ... closures, delivery-status, fast (3.14)` | ``check `closures` is red and `## Red checks` does not name it``, rc 1 |

The CI run was at 08:27:56Z; the reviewer blocked on `closures` at 09:42:56Z.
With a token the contract would have refused the body 75 minutes earlier, at

Every autofix commit is this shape: `closures-autofix` and `mutation-autofix`
push only after their red concludes, so the contract at the autofix head always
runs after the red it must name on the commit below it.

## 4. Process state: **(c)**

For class D: the process existed — #1144 built the arm, the contract runs it,
the reviewer's step 11 relies on its `record`/`skip` line — and it was followed.
It did not produce the intended result because its credential was never wired
into the one step that runs it. Not (a): the check exists. Not (b): nobody
skipped a step. Not (d): the token was absent from the day it landed, so no
precondition changed underneath it.

For A and B the state is #1985's (c), unchanged: the body is necessarily silent
at handoff on reds that do not exist yet, the contract and its rerun catch
them, and the review is dispatched at push (`orchestrator.md`) and may verdict
before or alongside the contract's refusal.

## 5. How far the class reaches

- **Other token-gated skips in CI.** `git grep` for `ghCredential`,
  `GITHUB_TOKEN`/`GH_TOKEN` reads in `tools/`, `.claude/workflows/` and
  `tests/*.py`: the other readers (`requireToken` for `--record`/`--stats`,
  `nightly_status.py`, `stamp.py`) refuse loudly or run in steps that carry the
  token. The body check's red history is the one silent skip found.
- **#1985's revisit trigger undercounts by construction.** It reopens the
  question when body-only repairs — "the PR's next verdict is `merge` at the
  same head" — reach 3 PRs in a window. `update_pr.sh` merges `origin/main` on
  every re-take, so a body-only repair almost never keeps the head. Measured
  instead as **zero own commits** between the blocked head and the next verdict
  head (main's merged commits and the delivery-row commit excluded;
  `next_verdict_own_commits.txt`): **7 PRs** — #2006, #2007, #2015, #2018,
  #2041, #2049, #2053 — against 1 under the same-head rule (#2006). The
  trigger is met; this RCA is that revisit.

## 6. Cost test and decision

Wall-clock, from the bus (`verdicts_review_refs.tsv`). The 7 body-only repairs
cost, block to next `merge` verdict: 13, 173, 27, 92, 81, 76 and 112 min —
**574 min over about 41 h**, median 81 min. By class: A 2 (#2007, #2049;
249 min), B 1 (#2018; 92 min), D 1 (#2053; 112 min), C 3 (121 min).

**Countermeasure built: the token on the body-check step.** One `env:` line
in `.github/workflows/pr-contract.yml`, pinned in `tests/entities.py`.

- Addresses state (c) for D: it makes the existing arm run.
- Standing cost: about 5 s per contract run (0.59 s without the walk, 5.56 s
  with it, measured on #2053's 6 branch commits), off every critical path —
  the contract runs beside a 45-minute `Tests`. No seat time.
- Saving: class D, 1 body-only round (112 min) in this window, plus every
  autofix-chain head after it.
- It changes no obligation: it moves a refusal the reviewer already issues to
  push time.

**Not built, with reasons.**

1. **A drafter of `## Red checks` run by `update_pr.sh`.** `update_pr.sh` runs
   at push, before the head's reds exist, so it can only see what the contract
   already sees. Run after settle, it duplicates the contract's own rerun,
   which in class A had already refused the body before the verdict. A draft
   can name a red but not answer it, and the answer is what class C's three
   blocks were about.
2. **`prepr.sh` refusing "none" while main is red on a context the diff
   reaches.** The contract already refuses that at push: #2058's aa88452d was
   refused at +0 for `delivery-status` (class A), 35 minutes before its
   verdict.
3. **Holding the verdict until the contract re-graded a settled head.** This
   is the lever for A and B (3 body-only rounds, 341 min here). It changes
   `fix-review.md` step 11 or `orchestrator.md`'s dispatch-at-push rule, which
   is policy. Proposed for the owner's decision, not landed: a reviewer
   returns `root-cause-unanswered` only after the head's workflows concluded
   and the newest `pr-contract` run at the head started after them; until
   then a red contract routes to the fixer for a body-only re-take. Standing
   cost: none in compute, a wait of up to one `Tests` run (about 45 min) on a
   review that would otherwise block.

**Revisit trigger, corrected.** Count a body-only repair by own commits, not by
head equality. Revisit when class A or B body-only repairs reach 3 PRs in one
window after this change lands.
