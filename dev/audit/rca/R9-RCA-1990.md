## 2. Cause

The issue recurs because two different things share one key:

- The rework arm (#1405, re-keyed by #1549) counts every re-verification after
  a `merge` as `head-moved`.
- The reviewer's own breach verdict is also `head-moved`.

In this window, 18 of the 20 entries are the sanctioned process doing its job.
`fixer.md` step 6 and `orchestrator.md` §11 require a new reviewer turn for any
head that is not a carry. In a 57-merge window, that crosses the threshold of
3 on every active wave.

Three concrete causes sit underneath the count, and each owns a class above.

1. **Class A: parallel siblings that write the same registries.** R9-RO-4,
   RO-5, RO-6 and RO-7 have the same `after` edges (`R9-RO-2`, `R9-RO-2b`), so
   the roster ran them in parallel. Their three-dot diffs overlap in all six
   pairs. `tests/closure.py` and `tests/closures.json` are written by all four,
   and `tests/entities.py` by three. Each merge broke the others' path-keyed
   gates. Each repair is the branch's own commit, so carry correctly refuses it
   and a new review is owed.
2. **Class D, now and from here on: the carry instrument is broken.**
   - R9-RO-6 (#1999, merged 2026-10-06T21:05Z) moved `app_approve.sh` and
     `preflight.sh` to `tools/pr/`.
   - R9-RO-5 (#1996, merged 2026-10-07T01:49Z) lifted the delivery rows to
     `dev/programme/delivery/`.
   - `tools/audit/seat/merge_train.py` still ran `tools/audit/app_approve.sh`
     (approve and carry), `tools/audit/preflight.sh`, and required
     `docs/delivery/<N>.md`.
   - Run at main, the train's carry step prints
     `bash: tools/audit/app_approve.sh: No such file or directory`, so it can
     never print `CARRY: yes`. The train stops at `carry` on every pull request
     (`evidence/carry-argv.txt`).
   - Its self-test stayed `43 checks, 0 failed`. The stub answers any argv
     that contains the basename `app_approve.sh`, so a missing path is
     invisible to it.
   - `merge_train.py` is the instrument that `INSTRUMENTS.md` names for "any
     merge queue", and the one that applies `orchestrator.md` §11's carry
     without a reviewer turn. With it down, every main sync costs a review.
3. **Class E: verdicts measured before the head settled.** #1977's row commit
   landed 7 minutes after the code head the reviewer measured.

The search for the same shape in the moved instruments, under
`tools/audit/seat/`, found more of class 2:

- `bus.sh`'s default poster was `$ROOT/tools/audit/app_comment.sh`. That path
  is missing, so a `bus.sh` run without `HPO_BUS_POSTER` cannot post. Its
  self-test pinned the stale string.
- `open_pr.sh` and `handoff_push.sh` write the PR's row to
  `docs/delivery/$N.md`. That directory no longer exists, so the write fails
  and no row commit is made.
- `handover_prompt.py` names `tools/audit/seat/app_push.sh` and
  `docs/delivery/<N>.md`. The first path never existed.

That first search matched script paths only (`.sh`, `.py`, `.mjs`), so it could
not return a directory or a document. The fix review of round 1 found one it
missed: `handover_prompt.py` sent every generated prompt to
`tools/audit/briefs/`, which RO-5 emptied into `dev/governance/roles/`.
Round 2 widened the search. `tools/audit/seat/moved_paths.py` reads every
path that `tests/layout.json` marks moved: each retired file no longer in the
tree, its emptied parent directory, and each lifted prefix; its count line says how many. It
reports every line in the five files that names one.

- Before round 2: 20 hits (`evidence/moved_paths_before.txt`, over round 1's files), the reviewer's line
  among them.
- After round 2: 12 hits (`evidence/moved_paths_after.txt`). Each is dispositioned in

  - `handover_prompt.py:14` and `:76` name `.claude/rules/`. `layout.json`

  - `handover_prompt.py:78`: the seat contracts' directory.
  - `merge_train.py`: four self-test fixture lines that modelled a policy

  - `handoff_push.sh`: its rule citation, its `HANDOVER.md` comment, and a

Round 3 ran the same instrument over all of `tools/audit/seat/*`, and walked

## 4. Cost test

`cost(countermeasure, recurring) < cost(defect) × P(recurrence)`, in
wall-clock per occurrence.

**CM-1, built: the train resolves the paths it runs, and its self-test reads
the real tree.**

- Standing cost: six existence checks and one regex in a self-test that
  already runs in `governance.yml`. Timings are within run-to-run noise: main
  0.91–2.13 s, fixed 1.27–1.83 s, 3 runs each (`evidence/time_*.txt`).
- Defect cost: class D's rate in this window, 3 in 57 merges, times its mean
  lag of 129 min, is about 6.8 min per merge. That figure is from before the
  train broke. Since the break, the train cannot land anything, and
  `merge_pr.sh`, which needs a verdict at the exact live head, is the only
  path.
- Verdict: passes by orders of magnitude.

**CM-2, refused: a sibling write-set check in `brief_lint.mjs`.**

- Standing cost: a new touch-set field authored on every roster group, plus a
  lint over it.
- Defect cost: class A once in nine rounds. Path reorganisation is the only
  wave in round 9 that produced it, at 276 min of lag over 11 rounds plus the
  repair commits.
- At one wave in nine rounds, the authoring cost on every group exceeds it.
  Refused.
- The remaining RO stages (RO-8 #1921, RO-9 #1922) are already serial: RO-9
  waits on RO-3 to RO-8.
- The finding that a move must re-point the seat instruments is carried
  in-tree to `.claude/workflows/carry-1921.json` and
  `dev/programme/carries/carry-1922.json`, with its control
  (`finding-propagation.md`).
- The roster brief copy, `handoff/round9/fix/RO.md` on
  `handoff/audit-r9-fixplan`, is the orchestrator's to update.

**CM-3, owner's decision, not built: stop proposing on the rework arm.**

- Proposal: the rework arm stops bumping `head-moved`. `STATS ROUNDS` already
  prints the re-verification count (18 here), so nothing goes unseen. A
  reviewer's own `blocked <sha> head-moved`, the real breach, keeps filing.
- Standing cost: none at run time.
- Defect cost: 7 filings in 14 days. Six recorded dispositions took a seat
  each (#1807 took two, plus this one), about 3 per week. Every active window
  re-files, because 18 of this window's 20 entries are sanctioned rework.
- Why it is not built here:
  - It reverses the keying that two judged findings pinned in
    `tests/entities.py`: #1405 D13-01 and #1549 D13-s1-01.
  - It changes what the owner-approved filer files (#959 B, #201 comment
    5670207248 item 4).
  - That makes it policy, and the question has been open since #1498.

**Class E: no countermeasure.** It is 2 entries in 20. The row-only commit
could be made carry-eligible by teaching `carry` to accept a commit that only
adds the PR's own row. At 1 in 57 merges, that does not pay for widening a
governance instrument's acceptance.
