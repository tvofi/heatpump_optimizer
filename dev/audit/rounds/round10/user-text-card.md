R10-USER-TEXT-VERIFY-CARD (the owner's ruling of 2026-11-13: verify all user-facing text in production against the actual code behaviour, not code comments). Method: the one PR #3513's user-docs record used, a claim table of page text against the deciding symbol, applied per string of the card's language table.

Merge base: `90c6bc3b0756475e28d4ace8d8e31c4788474933`; every `file:line` below is at that commit, paths under `custom_components/heatpump_optimizer/` unless they say otherwise, the card being `www/heatpump-optimizer-card.js`.

## The enumerator

`node dev/audit/harnesses/r10_card_user_text.mjs --tsv` lists every key of the card's `STRINGS.en` (the language table `L()` reads; `sv` and `de` key-for-key with it) and every unkeyed literal that reaches the DOM outside it (a template's `>text<` run, a `title`/`aria-label`/`placeholder`/`alt` value, a quoted `textContent`/`innerText` assignment). A key counts as reached when quoted outside the table, or when it starts with the literal head of a run-time key (`` `health.p_${...}` ``, `"health.input_" + id`). At the merge base it printed `table 648 (unreached 3)` and `literal 4`; the null control (a key and two unkeyed literals planted in a scratch copy of the card) printed `table 649 (unreached 4)` and `literal 6`, each planted string listed.

The four literals are unit suffixes (`h`, `kWh`, `°C` twice), the same in every language, so they stay unkeyed.

## Verdicts

Each row was judged by reading the code that decides it: where the card renders the key, under what condition, which value fills each placeholder, followed into the Python that computes it; never a comment. Rows that only name a thing (a tab, a button, a field label) claim no behaviour and are `n/a`. sv and de were read against en for every claiming row; a translation stating something else is judged for that language.
