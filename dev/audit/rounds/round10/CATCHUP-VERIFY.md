# Round 10 catch-up verification

The findings that missed the main verifier panel, each voted by one verifier carrying all three lenses (V1 reproduce, V2 independent, V3 reach and class). The method is refute-first, and every vote rests on an executed number. A `refute` backed by a number makes the finding `disputed`. A refute resting on timing alone is `unresolved`. The judge decides both. The full per-finding record (claim, both numbers, both metric definitions, null control, perturbation, attacks, notes) is `CATCHUP-VERIFY.json` beside this file. The harnesses the verifier wrote are under `catchup/<group>/`, with the votes each group returned.

- **Tree measured.** `origin/main` d749c986d. Production (`custom_components/`, `tests/`) is byte-identical at 554e2ecfa, 9061fbd3d, 17f1c55fa and d749c986d, so every baseline cited below is reproduced by this tree. The ARCH3-s6 prototypes were applied in a private copy.
- **Box.** macOS arm64, shared and loaded. Each timing row quotes its own `load1` (range 3.3–22.6) and `thread_factor` (≤ 1.03, except where noted in the JSON).
- **Null controls.** Added by the verifier wherever the finding lacked one, including the three D9 findings rejected at intake for this reason. Each was executed in the same session as its defect arm.
- **Not available as text.** The wave-2/3 finding texts (arch2-s1..s5, arch3-s6) are in no tree, commit or transcript. Each was reconstructed from its harness header, patch and commit message, as each row's notes say.
