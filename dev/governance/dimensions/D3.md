# D3 — Test-suite gaps

Owner's brief: *"Test-suite gaps — what the suite cannot fail on. Unnecessary
test suite resource use."*

Read `COMMON.md` first. You are the one finder with an **isolated worktree**
(with `.git`; `git log` and `gh` are still off limits) because your method
mutates production.

## Method: delete the line, re-run, see whether the suite notices

1. **Candidate list.** Parse every production module for guards (`if`,
   `min`/`max`/`clip`, `try/except`), constants that gate behaviour, and
   branches a user-facing claim depends on (payload keys, services, config
   validation, reason codes). Weight by consequence. Sample 30–40 mutants
   with a recorded seed, no module more than four, and record the weights.
2. **Pre-screen** each mutant with its **measured closure**
   (`tests/closures.json`): the fast scripts of that closure (skip
   `stress.py`, `edge.py`, `backtest.py` in the pre-screen) **plus**
   `tests/env_drift.py --all <baseline-sha>`. The differential gate is what
   CI runs; a mutant that moves any golden is caught there even when every
   assertion passes. A mutant pre-screened against the default five-fixture
   golden mode instead of `--all` produces a false gap.
3. **Report candidates, not findings.** Your output is a `prescreened` list:
   mutant patch, closure, which scripts ran, what killed it or that nothing
   did. The quiet window runs the full `GATE_SCOPE=full GOLDEN_MODE=drift`
   gate for the top six survivors; only those become findings.
4. **The verifier's question, answered in advance**: for every survivor,
   which single production line, in which file, and which check *should*
   have failed.
5. **Resource use.** Per-script wall and CPU from the gate table versus
   `closures.json`'s recorded seconds; assertions per solve; which scripts
   kill the same mutants (duplicated coverage); closures that over-approximate
   and force runs nothing needs; scripts that solve more than they assert.

## Reuse

`tests/closure.py select --diff` logic for the closure of a file;
`tests/run.sh` with `GATE_JOBS=1`; `tests/env_drift.py --all <sha>` with the
shared warmed cache; `tests/features.py:12382` for the mutation idiom.

## Traps

Run `stress.py` only in the quiet window, never during the fan-out; keep
`GATE_JOBS=1`; the comparison ref must be the baseline SHA, never `HEAD`;
`env_drift.py` adds a worktree in your checkout — one at a time.
