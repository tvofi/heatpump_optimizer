# D17 — Feature behaviour against its documented effect

Owner's ruling (tvofi, 2026-11-13): a dimension for feature behaviour against
its documented effect. *Each user-visible feature does what its documentation
and option say, in every state that reaches it.*

Read `COMMON.md` first. D6 checks that a sentence is true of the code; you
check that the feature does what the user was told, end to end.

## What you are hunting

A switch, option, service, button or blueprint that does not do, in some
state that reaches it, what `strings.json`, the docs and its own help text
say: no effect, a partial one, one in the wrong state, or one a restart loses.

## Method

1. **The universe.** `python3 tools/audit/enumerate.py d17-features`: every
   service, config and options field, input entity and blueprint. Per item,
   write its documented effect as one sentence with its source (file and
   key); an item with no documented effect is a lead for D5.
2. **The oracle** is that sentence, made an executable check before you
   read the implementation: what must be observable in the plan, the
   writes, the entities or the store with the feature on, and absent with
   it off. An oracle derived from the code is void (D3 step 6).
3. **End to end.** Set the feature the way a user does (the options flow,
   the service call through its schema, the entity's own method) on a
   coordinator built as `tests/entities.py` `_honest_coordinator` builds
   one, run cycles, and check the oracle in every plan state that reaches
   the feature (idle, heating, DHW, boost, away, manual plan), across a
   restart, and beside each feature it documents an interaction with.
4. **Null control and perturbation.** The feature off: the effect is
   absent. One state changed (a weekend, a holiday, presence toggled): the
   effect follows it.

## Escapes this dimension exists for

- Away: the override persisted while live away was off, so the plan heated;
  weekend and holiday comfort fields were not set back; presence was read
  on a 30-minute lag.
- Space boost wrote a partial flow set-point; the test drove idle only.
- Config-flow help said the optimizer never writes a recommended space
  set-point; it had since September.

## Traps

A test that already passes is not your oracle. Where the effect is a
written value, D16 owns the value and you own whether it happens at all.
