# D6 — README and documentation claim verification

Owner's brief: *"README and other documentation claim verification — every
claim against actual code and data."*

Read `COMMON.md` first. D5 owns structure and flow; you own truth.

## Method

1. **Extract every claim.** From `README.md`, `docs/*.md` (except the
   audit records), `DISCLAIMER.md`, `services.yaml`, `strings.json` and the
   translations, `manifest.json` and `hacs.json`: every sentence with a
   number, a default, an entity or service name, a field, a unit, a
   behaviour ("the optimizer will…"), a performance statement, a version
   or a link. Number them.
2. **One executed check per claim.** Defaults against `const.py`; entity
   names and counts against `tests/entities.py:collect` through the real
   `async_setup_entry`; service fields against the voluptuous schemas and
   `services.yaml` examples fed through those schemas; behaviours against a
   golden scenario or a small harness; performance claims against a
   measurement (provisional under the fan-out); versions against `VERSION`
   and the tag list in the export's `manifest.json`; links with a HEAD
   request.
3. **The claims table**: id, source, claim, check command, result,
   verdict (`true` / `false` / `stale` / `unverifiable`), and for a false
   claim what the true statement is.

## Numbers

Claims extracted, claims checked, claims false, claims stale, claims
unverifiable — with the table as the harness output.
