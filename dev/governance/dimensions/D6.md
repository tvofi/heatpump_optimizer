# D6 — README and documentation claim verification

Owner's brief: *"README and other documentation claim verification — every
claim against actual code and data."*

Read `COMMON.md` first. D5 owns structure and flow; you own truth.

## Method

1. **Extract every claim** from the files your cells name and the live
   https://tvofi.github.io/heatpump_optimizer/: every sentence with a
   number, default, entity or service name, field, unit, behaviour,
   performance statement, version or link. Number them.
2. **One executed check per claim.** Defaults against `const.py`; entities
   against `tests/entities.py:collect` via `async_setup_entry`; service
   fields against the voluptuous schemas, and `services.yaml` examples fed
   through them; behaviours against a golden scenario or harness;
   performance against a measurement (provisional under the fan-out);
   versions against `VERSION` and the tag list in the export's
   `manifest.json`; links with a HEAD request, which never sends a
   `#fragment`: anchors on the web page and its sub-pages (D6-s1) by
   `dev/audit/harnesses/d6_page_anchors.py`, in the tree and live. Pages
   deploys the latest `v*` tag: diff the live page against its
   `docs/index.html`, not the baseline's.
3. **The claims table**: id, source, claim, check command, result, verdict
   (`true` / `false` / `stale` / `unverifiable`), the truth if false.
