# D6 — README and documentation claim verification

Owner's brief: *"README and other documentation claim verification — every
claim against actual code and data."* Scope (tvofi, 2026-11-13; 1 = all user
facing text in production, 2 = every single sentence in all documentation,
3 = all code comments): *"Do 1 in round 10, and 2 and 3 in round 11 sequenced
as you recommend. Code comments in instruments and the documents that describe
the instruments, developer and other non-static documentation also in scope
for 3."* *"The test suite comments are in scope. Also, since 1-2 is done before
3, they may not trust code comments, only the actual code behaviour"*. *"Go by
your recommendation, but I would like the scope of d5 and d6 to always cover
that full scope"*.

D5 owns structure and flow; you own truth, run before D5's comment pass.

## Method

1. **Row every unit** `tools/audit/text_ledger.py units --dim D6` lists for
   your cells, and the live Pages site: a claim is any fact the code, data or
   page can falsify.
2. **One executed check per claim** against the code deciding the behaviour,
   never a comment: defaults in `const.py`; entities by
   `tests/entities.py:collect`; services by their schemas; links by HEAD,
   anchors by
   `dev/audit/harnesses/d6_page_anchors.py`, the live page against its tag's
   `docs/index.html`. A key-parity check is no truth check.
3. **`text_ledger.py check --plant`** refuses a skipped unit. One finding per
   file holding a false or stale row; its harness output is `check`'s.
