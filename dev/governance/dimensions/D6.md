# D6 — README and documentation claim verification

Owner's brief: *"README and other documentation claim verification — every
claim against actual code and data."*

Read `COMMON.md` first. D5 owns structure and flow; you own truth.

## Method

1. **Extract every claim.** From `README.md`, `docs/*.md` (not audit
   records), the web page (`docs/index.html`, `docs/site/`, published
   https://tvofi.github.io/heatpump_optimizer/), `DISCLAIMER.md`,
   `services.yaml`, `strings.json`, translations, `manifest.json`,
   `hacs.json`: every sentence with a number, default, entity or service
   name, field, unit, behaviour, performance statement, version or link.
   Number them.
2. **One executed check per claim.** Defaults against `const.py`; entities
   against `tests/entities.py:collect` via `async_setup_entry`; service
   fields against the voluptuous schemas; behaviours against a golden
   scenario or harness; performance against a measurement;
   versions against `VERSION` and the tag list; links and anchors with a
   HEAD request. The web page also: the live page against
   `docs/index.html` at the baseline (published drift), and its version and
   feature list against `README.md` and `RELEASE_NOTES.md`.
3. **The claims table**: id, source, claim, check command, result, verdict
   (`true` / `false` / `stale` / `unverifiable`), the truth if false.

## Numbers and exposure

Claims extracted, checked, false, stale, unverifiable, with the table as
the harness output. Record the audit-era documents you had to open in
`exposure`.
