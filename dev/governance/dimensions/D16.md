# D16 — Actuator-write safety and liveness

Owner's ruling (tvofi, 2026-11-13): a dimension for actuator-write safety and
liveness. *Every write the integration makes to a real heat pump is bounded,
intended, and never held without an automatic release.*

Read `COMMON.md` first. You have an isolated worktree for the upgrade arm:
`git show <tag>:<path>` for an earlier release's writer, nothing else of `.git`.

## What you are hunting

A write to a pump entity that is wrong, out of range, stepped too far or
never made: a hold with no release, a latch that outlives its cause, a
restore to the wrong baseline, two writers deadlocked. D1 owns whether the
cycle survives and D12 whether a surface is supported; you own the value
written and whether it is ever released.

## Method

1. **The universe.** `python3 tools/audit/enumerate.py d16-writes --cells`:
   every service call and every `log_held` site in the package, crossed with
   the duty modes and with running, restart, upgrade and unavailable. A
   write path it misses (a registered writer, a helper) is a finding
   against the enumerator first.
2. **Drive each cell**, never one point: every plan state that reaches the
   site (idle, partial, full, boost, DHW-only, off, away), on D1 step 1's
   real-loop harness. Restart: persisted state reloaded. Upgrade: the state
   an earlier release's own writer wrote (D1 step 7). Unavailable: the
   target and each input entity `unknown`, `unavailable`, then back.
3. **The written value.** Per write: it equals the documented target for
   that plan state (docs, strings, the option's help), lies inside the
   entity's `min`, `max` and `step` and the configured range, moves by no
   more than the configured step, and repeats no more often than the
   configured writes per day.
4. **Liveness.** Per hold, latch and refusal: enumerate its state space,
   every flag and persisted field that gates the write, as a transition
   table, and show from each reachable state a path to "writes again" that
   needs no person: no restart, no option change, no service call. A state
   with no such path is a finding; so is a table you cannot close.
5. **Restore.** Off, unload, remove and a duty-mode change: every entity
   the integration wrote returns to the value it had before, once, also
   when an earlier release recorded the baseline or the entity was
   unavailable at the time.

## Escapes this dimension exists for

- v7.1.12 to v7.1.15: after an upgrade the flow set-point write was held
  with no release (#3404), and the suite's upgraded-install test asserted
  the hold as intended.
- Since v6.7.17: space boost wrote a partial flow set-point; the test drove
  an idle plan only.
- #3380: set-point feedback wrote the modulation floor.

## Traps

A write the stub accepts is not one Home Assistant accepts
(`tests/ha_contract.py`). A hold is legitimate when its release is
automatic: report the missing release, not the hold.
