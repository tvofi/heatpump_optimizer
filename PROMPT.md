> Answers to the two questions (ha-luxtronik-shi, FW 3.92.3):
>
> 1. Polling: yes. ha-luxtronik-shi polls every 30 s by default; the option is limited to 10-300 s on purpose, so it always stays below the 600 s watchdog. So while the integration runs, values written by the HPO are not dropped by the watchdog. >
> 2. All three are readable as Home Assistant sensors today, enabled by default, read every 10th poll (about 5 min at the default interval):
>    - input 10107, key `heating_demand_border` ("Demand border"): firmware item t0/0x57, effective return target minus hysteresis (proven)
>    - input 10104, key `return_min_target` ("Temperature: return target minimum"): parameter 979, lower clamp of 10001
>    - input 10103, key `return_limit` ("Temperature: return limit"): parameter 87 Einst_TRBegr, upper clamp of 10001
>    The firmware clamps the heating setpoint 10001 to [10104, 10103] (section 3.1), so the design can read both bounds over the SHI; no parameter interface needed. They are read-only on the SHI.
