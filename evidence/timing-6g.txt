## The loop alone, and the one-line cause
`--print-link-targets` at the head prints 84 targets (85 in the fixture, which
adds one unlisted link).
Loop over a whole-tree copy (every target present, no archives at all):
  per-target `python3 -I -c 'import os,sys; ...normpath...'`   2.84-3.12 s CPU
  the same loop normalising in-shell (no per-target interpreter) ~0.0-0.16 s CPU
One `python3 -I -c 'pass'` 0.03-0.034 s CPU; 84 spawns ~= 2.6-2.9 s CPU.
(timing-loop.txt: 84 targets, python arm 2.84 CPU, shell arm 0.00, one spawn 0.03.)
`python3 claims.py --print-link-targets` alone 0.17 s CPU; the copy 0.22-0.24.

The step runs the interpreter FOR EVERY target before the `[ -e ]` test that
would have skipped it: prepr.sh, claims_reg_line, the `rel=$(python3 -I -c ...)`
inside the `while ... done < <(... --print-link-targets)` block.

## What the loop buys on this tree
`python3 -I dev/audit/rounds/round4/D6/claims.py --print-link-targets` at the
head prints 84 targets; all 84 are already inside `CLAIMS_INPUTS` (0 outside).
So on an ordinary docs diff the loop takes the `[ -e "$2/$rel" ] && continue`
branch 84 times and archives nothing: ~3.1 s of CPU to copy 0 files. The step's
own comment says as much ("Today's targets are all in CLAIMS_INPUTS, so an
ordinary docs diff adds no archive here"), which makes the spawn the whole cost.
A normalisation in-shell, or a generator that prints targets not already under
`CLAIMS_INPUTS`, removes it (0.16 s CPU for the same loop).
