Finding 2 — the ACCEPT does not meet proposal-triage.md's bar
=============================================================

The seat's own contract, dev/governance/roles/proposal-triage.md:
  "**The bar is 'clearly'.** A proposal is wired in only when its measured
   benefit clearly outweighs everything it adds: wall-clock or seat time on the
   critical path; tokens ...; GitHub API calls; standing CPU ...; code and policy
   complexity (lines, new files, new checks, hot files touched, review rounds);
   and maintenance surface. An even or marginal trade is REJECT; **an unmeasured
   benefit is DEFER, never ACCEPT.**"

The instance is already healed by the batch's own remedy (its lines 14-15):
  "A zero-code remedy exists for this instance and costs one command:
   python3 -I tools/audit/seat/ledger.py dispose <ref> <sha40>."

Read-back at the default home ($HPO_STATE_DIR unset -> ~/.local/state/hpo):
$ python3 -I tools/audit/seat/ledger.py disposed refs/heads/handoff-body/r10-flow-jidoka-p2-body b9b690afb9830a20e046b3515bd18858757d2047

A full level pass at the default home no longer owes it:

So the measured benefit for the one instance is zero: the dispose already removed
the line. What remains is the benefit for future STOP bodies, which the batch does
not measure.

$ for r in <each fetched refs/hpo-review/handoff-body/*>; do first=$(git show "$r:BODY.md" | grep -m1 -v '^[[:space:]]*$'); printf '%s' "$first" | grep -qE '^#{1,6}[[:space:]]*STOP:'; done | wc -l

Exactly one STOP body in the whole corpus, and it is the one already disposed.
The batch's own text is "Instances: one". An ACCEPT whose only measured benefit is
already delivered by a one-command remedy, with the class frequency unmeasured, is
the "unmeasured benefit" the contract sends to DEFER ("names what would change the
answer": a second STOP body, or a measured rate).
