## Block

- `draw_range._stored_map` (custom_components/heatpump_optimizer/draw_range.py, `split = [c.split(",") if c else [] for c in cols]`) reads an empty column string as zero cells, but `MapRows.as_columns` writes `""` for a column whose single row's cell is unread (None). With exactly one stored row and any unread cell, the column lengths come out 1 against 0, the "unequal length" rule fires, and every row is dropped. Reproduced at the head (`ev/roundtrip_one_row.log`): a row from an install with no inlet sensor (`inlet_mean_c`, `inlet_change_k` None) gives `stored_rows=1 reloaded_rows=0`; the same with two rows gives `2 -> 2`, and one fully read row gives `1 -> 1`. So the first committed row is lost on any reload while it is still the only row, on every install that leaves some cell unread (no inlet sensor, no outdoor reading, an unread band end). The design asks for rows "kept and persisted" (A Storage) and for older stores read with no migration; persistence that does not read back its own write is not that. The branch's own check at tests/features.py "a single row with unread cells stores empty column strings, which the domain admits" pins only the write and the domain, never the read-back, which is why the suite is green. Fix suggested: split every column unconditionally (`as_dict` never writes `map_rows` with zero rows, so `""` always means one empty cell), and extend that check to `DrawRange.from_dict(_mr_one_row.as_dict()).map.rows` equalling the row. A small fix; everything else below verified clean, so round 2 should be a short delta review.
