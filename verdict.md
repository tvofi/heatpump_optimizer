## Revise points

- R1 (F1, plus the existing hold mechanism). The note has no anti-windup against the controller's own clamp. In design.md §3, the clamp `lo = max(inlet - DOWN_K, gate + step), hi = flow_heat_c` is HPO's own. The controller cuts 10001 to [parameter 979, Einst_TRBegr], and HPO reads neither. A W beyond that range is cut, and the reading then differs from the record. At that point `hold` (`pump_arbiter.py:1051-1072`) drops the record and rewrites. On a second miss, `_not_held` raises `ISSUE_IGNORED` and retries every `RETRY_MINUTES`. Meanwhile W keeps integrating toward `flow_heat_c` or toward lo. When the error changes sign, W must travel back through dead range before the controller sees any change. Fix wanted: the note states an anti-windup rule built only on the existing readback, with no new read path. For example: after `ECHO_GRACE_S`, a reading on the bounded side of a write freezes W at that reading in that direction. The note also states whether a cut the loop caused raises `ISSUE_IGNORED` or is exempt from it. A test pins both.
- R2 (F2). The note assumes today's write starts the pump. At the controller's default hysteresis it does not. Three places rely on that assumption: the pseudocode line `if not running or record empty: W = base  # today's write: start past hysteresis`, invariant I3, and proposal item 4. At the default 2 K (the range is 0.5-6 K), inlet + `flow_min_lift_k` 0.5 K never starts a stopped compressor. The loop also creates a new path to that state: it drives W down to inlet - 1 K. If the compressor then stops, the `not running` branch resets W to base, which stays below the start threshold for the rest of the step, and the step delivers nothing. Fix wanted: the note picks one option. (a) Keep today's start write as a recorded limitation, with a user-docs line saying the hysteresis must be at most `flow_min_lift_k`. (b) Aim the start write past input 10107. That needs a new read path, which the brief excludes, so it becomes `decision: owner`. The note must also state what the loop does after a stop it caused itself: whether lo keeps W above the controller's stop condition, or the loop accepts the extra start that the acceptance criterion forbids.
- R3 (F4). The note's deadband branch holds W and writes nothing. It does not say what keeps the SHI's 600 s volatility timer re-armed, or how the loop recovers after a revert. Fix wanted: (i) Name the access guarantee. Either it is the integration's own polling, stated as a precondition with a user-docs line, or HPO re-writes the held value at least every 10 min. (ii) State the recovery. A revert of 10001 to 35.0 °C is caught by the existing `hold` readback (`pump_arbiter.py:1051-1065`), and the note should say whether that rewrite also resets the loop record. A revert of heating mode 10000 to 0 (the curve) is not an HPO-held slot. Today the set-point writes would then be ignored with no readback difference, so the note states how the arbiter notices this, or records it as a limitation.
- R4 (evidence plan, item 6.1; harness). The simulated controller has no start threshold, no stop condition, no clamp and no revert. So the "one start" assertion cannot fail, and the fixture never exercises R1-R3. Fix wanted: the fixture models these four things:
  - start only when the return is below W minus the hysteresis, run at both 0.5 K and 2 K;
  - a stop condition;
  - a [parameter 979, return limit] clamp on W;
  - a revert after 600 s with no access.
  The gain k is calibrated to about 0.9 Hz/min per K, citing F6 as an install measurement, not a firmware fact. Item 7's mutation targets add the anti-windup freeze and the start/stop path, and each mutant must fail one of the item 6.1 repeats.
- R5 (F3, F5, F6). These need a recorded answer, not a design change. Fix wanted: one line each in the note.
  - F3: the 0.1 K main run and the 0.5 K repeat already match the firmware's 0.1 K resolution. No constant is in kelvin of deadband (DEADBAND is kW).
  - F5: a user-docs line saying no second tool may write 10000/10001 (error 816 silently discards writes). The rate limit is per loop, not per writer.
  - F6: START_HOLD 5 min covers the measured 3 min start programme.
  The docs file then joins §7's hot files whatever the owner answers on the option, not only under that answer.
