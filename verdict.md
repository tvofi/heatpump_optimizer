## Block

The generic `except Exception` translates that into a transport fault: the worker is killed and `ProcessWorkerUnavailable("exited rc=None: ...")` is raised, so every solve on such a host falls back in process. That repeats every cycle while the pipe's fd stays high (each respawn takes the lowest free fd), and the repair issue follows after WORKER_FALLBACK_CAP cycles. Main serves the same call.
   Home Assistant raises its own soft RLIMIT_NOFILE to 2048 (`homeassistant.util.resource.DEFAULT_SOFT_FILE_LIMIT = 2048`, read from /opt/hpo/venv-ha), because real installs exceed 1024 descriptors. This PR also adds a new respawn trigger (the timeout), and a respawn happens at runtime, when the fd table is fullest.
   Measured (ev/probe.out, ev/probe.py `fd` mode, 1100 fds held, RLIMIT 4096):
