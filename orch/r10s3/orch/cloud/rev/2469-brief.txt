R10-UPDATE-PR-LOCK, the RCA fix for worktrees vanishing mid-prepr (2 incidents on 2026-10-19/20). Mechanism: update_pr.sh uses a fixed worktree $HPO_STATE_DIR/pr/upd-<branch> and force-removes it at start (update_pr.sh:35 at d1db05dfc); cloud_relay.sh pass's handoff arm (cloud_relay.sh:199-200) auto-runs update_pr.sh on the same branch as a manual run, so the second run deletes the first's live worktree. Fix: an exclusive per-branch lock on upd-<branch>.lock taken via python3 -I before any fetch or worktree change. A held lock prints BUSY and exits 75 with no change; other lock errors REFUSE; the push runs with the lock fd closed. cloud_relay.sh treats 75 as retry-next-pass, not failure. INSTRUMENTS.md documents the retry. Verify adversarially:
(1) the lock is taken before every mutation, including fetch, worktree remove/add and the log write, and released on every exit path and on SIGKILL (kernel-released);
(2) no child process inherits the lock fd;
(3) a stale lock file from a dead run does not block (null);
(4) exit 75 cannot mask a real failure in the relay;
(5) open_pr.sh and app_push.sh share no other fixed path that races the same way. If they do, it is a finding: fix or carry.
