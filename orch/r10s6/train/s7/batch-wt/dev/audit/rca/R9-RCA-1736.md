## 1. The named cause

**The three configured hub objects double as the solve's input-assembly
surface: `async_run_optimization` and `_prepare_dhw_inputs` write each solve's
effective values in place into the live `_opt_config` / `_thermal_params` /
`_current_state` before the snapshot, and because those writes are *meant* to
persist — they are recomputed from config on every cycle, so no unwind is owed —
the only group ever given an envelope is the away setback, the one group whose
design intent is temporary; the hubs therefore permanently carry two meanings
(configured value vs this-solve's effective value), and every concurrent reader
or mid-solve writer is one missing "configured, never live" lesson away from
being the next instance of the class.**

## 2. Process state

Two levels, and they have different states — recording the second as the first
is the error `root-cause.md` §2 warns about.

**(a) The process did not exist — for the landing of each instance.** No rule,
brief line, check or budget distinguishes a solve-scoped write into a live
shared object from a persistent one. `tests/structure.py` measures size, edges
and cut metrics; nothing counts or constrains write scope. Every per-solve
write site passed ordinary review as a reasonable-looking refresh (and the
persistent ones genuinely are); every defect was found after the fact by an
audit dimension or by a reader being taught. Evidence: none of #240, #1517,
#1529, #1683 triggered any check at the commit that introduced or carried it.

**(c) The process existed, was followed, and did not produce the intended
result — for the class going unrecognized for three rounds.** Two instruments
existed and ran:

- **The per-round class sweep** with the barrier rule
  (`defect-root-cause.md`: *"three or more instances in one round … owes a
  class-eliminating barrier"*). Followed exactly; its counting window is the
  round. This class never reached 3 inside one round — round 8 filed #1517 and
  #1529 as two adjacent but differently-shaped D1-s1 findings; round 9's judge
  named the class and recorded N=1. A class recurring **across** rounds at 1–2
  per round cannot fire a per-round trigger. This is state (c) by definition:
  the sweep was obeyed and wrong, so the countermeasure is a window fix, not a
  firmer instruction.
- **The cross-round ledger** `tools/audit/bugclasses.json` (seeded from the
  round-8 classification of rounds 1–7, `"surviving findings only, one
  mechanism class per finding"`). Searched at main: **none of the five
  instances appears under any class** — #240 was labelled `bug (provisional)`
  before the class vocabulary existed, and the round-8/9 filings were never
  folded in. The one instrument that counts across rounds never received a
  single member of this class.

Recognition finally came from **outside both instruments**: the owner-directed
round-9 endgame architecture review (`ALT-ENDGAME-PLAN.md` §2), which read the
four closed issues as one class.

## 3. How far the class reaches

- **Coordinator-wide census** (m1 enumerator at `c54b20d2`): 65 in-place hub
  write sites over 50 fields. Per-function attribution (this seat's extension,
  62 direct-attribute sites in 15 functions + 3 `setattr` sites inside
  `async_update_thermal_params`):
  - **Solve-scoped (the class): 26 sites / 23 fields** —
    `async_run_optimization` (19), `_prepare_dhw_inputs` (7).
  - **Event-driven configured-state producers (not the class): the remaining
    39 sites / 13 functions** — `_update_current_state` (19, the per-cycle
    state refresh), `async_update_thermal_params` (4+3 setattr, the
    `set_thermal_parameters` service — the writer #1517's user was using),
    ecl110 state messages (2), `_apply_comfort_weight` (2), learner/COP/scale
    appliers and single-site loaders (8 more). These change the configured

- **Outside coordinator.py**: only `away.py` writes into the hubs
  (`apply_setback` + `lower_floor`, 8 sites) — all of it the envelope EG-B1
  deletes. No other module writes the three hubs.
- **Readers that have already been taught** (each a prior instance or rule):
  `async_simulate` deep copy (#240), `async_diagnose_interval` snapshot
  (#1529), `target_temperature` from entry options (#1683), the mold-guard cap
  rule (`coordinator.py:8361`), the price-tile target choice
  (`coordinator.py:10175`ff, "perturb the LIVE target… or the published trade

  proving the two meanings are both real and reader-dependent).
- **Unmeasured leads carried from the issue** (static reading only, this seat;
  the runtime harness is EG-B1's acceptance instrument, §5): `async_simulate`
  assembles its own argument list, so by reading it passes none of the

  **18.4 h** (n=2). Audit-side seats add the round's finder/verify/judge cost
  per instance, not counted.
- **Escape** (first trigger of `defect-root-cause.md`): **every tagged release
  from v3.8.0 (2026-08-24) through v6.7.6 (2026-09-27) — 115 consecutive
  releases** (tag dates from `git tag --format`) carried at least one live
  instance: the unconditional restore (#1517's shape) from the setback's
  introduction to v6.6.11, and the climate entity publishing the setback
  target (#1683) to v6.7.6.
- **P(recurrence), measured**: 5 instances in 33 days (2026-08-26 →
  2026-09-28) = **4.6 per month**, one per 6.6 days, across three rounds with
  no round reaching the per-round barrier trigger.
- **Expected cost without a barrier**: 4.6 × 18.4 h ≈ **85 h wall per month**
  (lower bound), plus whatever fraction ships unnoticed — and §3 shows the
  shipping fraction has been 100% of instances so far, for a median of ~3
  weeks each.

**Barrier side.** EG-B1's *standing* cost (the left side of the test) is
≈ **zero**: it replaces 26 in-place writes with the construction of one frozen
record per solve — less work, not more — deletes `away.py`'s envelope (code
down, `coordinator_loc` down), and adds no per-run check. Its one-time cost is
one PR at F1.1/#1563 scale (measured proxies for that scale: PR open→merge
1.8 h–10.3 h, plus one high-effort fixer session and one adversarial review).

**Verdict: 0 standing < 85 h/month recurring — the test passes by any margin;
even the one-time cost is repaid by preventing a single next instance.**

## 5. Countermeasure: EG-B1 (per-solve immutable inputs) — verdict

**Build it. It eliminates the class, it does not guard it.**

- **Does it eliminate the class?** Yes, for the 26 solve-scoped sites: if each
  solve builds one frozen input record — setback as a value in it — and the
  configured objects are never written on the solve path, then *no solve-scoped
  hub write can exist to leak*: the two-meanings mechanism is removed at the
  producer, which is the only place all five instances' readers and writers
  meet. The `away.py` compare-and-restore envelope is **deleted, not
  extended** — the right direction, since #1517 showed every envelope repair
  breeds its own next instance. The remaining 39 hub-write sites are
  event-driven producers (§3) and are out of the class by definition.
- **What it costs.** One F1.1-scale PR (one-time, §4) and its **after-edges**
  (the plan's EG-B1 row): F10.4, F2.4, F10.6, F11.5, EG-B0, EG-B4, EG-B5 —
  i.e. it is sequenced last in the EG lane, after the round's fix stamp, so
  its schedule cost is serialization at the tail, not build cost. Structure
  budgets move *down* (envelope deleted, `coordinator_loc` falls); any raise
  is asked before push per the plan's owner gate.
- **Obligations this RCA adds to EG-B1's brief** (the countermeasure must be
  shown to counter):
  1. **Null control**: byte-identical goldens (already the plan's rule — a
     golden that moves means it is not the pure refactor it claims).
  2. **Acceptance harness for the two unmeasured leads** (§3): live solve vs
     what-if on identical inputs, two arms — setback active, setback inactive —
     with the inactive arm required identical (that is the null control); run
     in the hpo-ci container under the HOST-side gate_lock lease rules. A real
     parity gap found here goes to tvofi as a separate product decision, per
     the issue — not a rider on the refactor.
  3. **Barrier demonstration** (`defect-root-cause.md`: a countermeasure must
     be shown to detect/eliminate): re-run `m1_hub_writes.py` at EG-B1's head —
     it must report **0 solve-path hub writes** and 0 restored fields (the
     envelope gone), against the 23/6 at `c54b20d2` recorded above; the
     control arm (restored ⊆ written) stays trivially True.
- **The (c)-state countermeasure** (the counting window), beside the barrier:
  fold the class into `tools/audit/bugclasses.json` with all five closed
  instances (#240, the mold-guard rule, #1517, #1529, #1683) at EG-B1's merge,
  so the next cross-round class starts at its true count in the one instrument
  that counts across rounds. That is a data file, not policy; it rides the
  EG-B1 or record PR. Whether the per-round window of the barrier rule itself
  should widen to see cross-round recurrence is **policy** (it lives in
  `defect-root-cause.md`) — proposed to tvofi here, not landed: as written,
  a class at 1–2 instances per round never owes a barrier no matter how many
  rounds it spans, and this class is the worked example (5 instances, 3
  rounds, 115 escaped releases, trigger never fired).
