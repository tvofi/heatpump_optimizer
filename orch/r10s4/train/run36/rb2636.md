seats not post claude code footers, especially not with direct links to

What changes:

1. **The source.** `.claude/settings.json` sets `"attribution": { "commit": "",
   "pr": "", "sessionUrl": false }`. The settings reference
   (code.claude.com/docs/en/settings-reference.md, section `attribution`) gives
   the types: `attribution.commit` and `attribution.pr` are strings, and an
   empty one hides that attribution. `attribution.sessionUrl` is a Boolean, and
   `false` omits the `Claude-Session` trailer and the PR link. The page also
   allows `attribution: false`, but only from v2.1.281; earlier versions
   "skip the whole ... settings file that holds it". So this file uses the
   page's form for "a settings file that earlier versions also read" (empty
   strings and `false`). `includeCoAuthoredBy` is deprecated, and Claude Code
   ignores it once `attribution.commit` or `attribution.pr` is set. It is not
   used here.
2. **The guard.** The existing instruments are extended; no new lint class is
   added. `tools/audit/seat/ref_privacy.py` gains `ATTRIBUTION`, four classes:
   - `session-link`: a claude.ai session URL (`claude.ai/code/` followed by a
     session id);
   - `session-trailer`: a `Claude-Session:` trailer;
   - `co-author-trailer`: a `Co-Authored-By: Claude` trailer;
   - `generated-footer`: the generated-by-Claude-Code footer line, in its
     emoji, bullet or italic form.

   A trailer or footer counts only at the start of a line, where git reads a
   trailer, so prose quoting one mid-line passes. Three places judge text on
   these classes:
   - `refusal()` judges commit messages on them. That covers `guard --commits`
     for app_push.sh and push.sh, and the composed messages of body_push,
     bus.sh, heartbeat and roster_edit.
   - `body_refusal()` judges comment bodies on them, which covers
     `gh_comment.py`.
   - `tools/policy/policy_lint.mjs` `checkPrBody` refuses the same classes in a
     PR body. That is the body contract that prepr.sh, body_patch.sh,
     `app_push.sh --row-only` and CI's pr-contract all run.
3. **The prompts.** `tools/audit/seat/cloud_dispatch.py` adds `FOOTER_BAN`, one
   line in every role's rendered prompt.

Alternatives considered for the body contract's grammar:
- **policy_lint.mjs spawns `ref_privacy.py`, so there is one copy.** I built
  this first and then dropped it. pr-contract restores its programs from the
  base so that it "runs no pull-request program at all" (decision 0013), and
  `tools/audit/seat/ref_privacy.py` is not in that restore list. The spawn
  would have executed the pull request's own Python there. tests/entities.py
  also caught it: its autofix-head fixture copies policy_lint.mjs into a tree
  without ref_privacy.py.
- **A shared JSON data file.** A pull request could then weaken the grammar and
  pass its own contract, which the base-restored copy prevents. It would also
  be a new tracked file to classify.
- **Two readers held together by agreement.mjs. This one was taken.**
  `agreement.mjs`'s new `attribution` pair compares the two readers. Its corpus
  is the last 400 commit messages plus boundary probes: CR and U+2028 line
  breaks, a long-s that only Unicode case folding reads as `s`, `Claudette`,
  `Claudeé`, mid-line quotes, and a non-session claude.ai URL. So both readers
  are written to the same terms: ASCII case folding, explicit
  `(?![A-Za-z0-9_])` word edges, and Python rewriting `\r`, `\r\n`, U+2028 and
  U+2029 to `\n`, where JavaScript's `^` already opens a line.

**Main is not charged.** The guard judges only `--not --remotes` commits, the
ones a push publishes for the first time. `--check`'s content arm keeps
`leaks()` without the attribution classes, because tracked files name these
lines in order to forbid them. On main's CI, `ref_privacy.py --self-test` and
`--check` are the steps that run, and both pass at origin/main with the new
code (see Figures).

- **With this branch's `attribution` block:** the commit message is the subject

- **With main's settings (the control):** the same request committed a

Neither run had a git-level hook or a commit template; `git config` named none.
So the trailer comes from the harness's instructions, and the setting turns
them off.

**Known limit (not a finding against this PR).** The cloud environment's system
prompt carries its own "attribution footer on every GitHub post" instruction,
and no repository setting reaches it. `gh_comment.py` (body_refusal) refuses
that footer, and the prompt line in item 3 states the ban. A comment posted
straight through the GitHub MCP tools, bypassing gh_comment.py, is not guarded.
That path already breaks `comment-readback.md`.
