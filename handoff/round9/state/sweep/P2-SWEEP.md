# Class P2 sweep — round 9, thread S1

**Property**: one fact decided twice by divergent predicates — a guard, freshness rule, tz-normalisation, threshold, domain check or canonical-predicate call exists at one seam and is missing (or diverges) at its sibling seam that decides the same fact.

Baseline: `1936d5ca72a06556eeed4e8e5bf3dea520e517e1` (v6.7.1). Branch cut from `handoff/audit-r9-judge` (bad458a3, CLASSES-DRAFT.json final). Machine: cloud sweep container, CPython 3.11.15 (the round's own venv314/venv/venv-r9 were not present on this box; every harness below was re-run with plain `python3` + `PYTHONPATH=tests/hastub`, after installing `voluptuous`, `aiohttp`, `numpy`, `scipy`, `orjson`).

## Method

1. **Enumerator.** `enumerator.py` in this directory is D14-s2-01's own canonical detector (`p2_facts.py`), copied here unmodified: it AST-extracts the canonical predicates for `two_zone_enabled`, `dhw_enabled` and `wood_furnace_on` from their defining functions, then scans the *whole* `custom_components/heatpump_optimizer/*.py` package for decision-context reads of the same proxy keys outside those predicates. This is the one fact in the class with a package-wide mechanical enumerator; the other 26 findings are each keyed on a different fact (a different guard, threshold or parser), so each was widened from its own `seam_rule` instead of a single shared AST scan — the class is defined by a *shape* (divergent predicates for one fact), not by one canonical predicate list.
2. **Per-finding widening.** For each of the other 26 findings, its `seam_rule` (already committed on `handoff/audit-r9-evidence` inside `JUDGE-INPUT.json`/`JUDGE-INPUT-B.json`) was re-run verbatim (fixing two brace-expansion greps that need `bash -c`, not `sh -c`) against the files it names, and read for any call site beyond the ones the finding already cites. Seven findings (noted below) turned up additional matches; each extra match was read in place and dispositioned.
3. **Positive control.** Every finding's own harness or seam_rule command was re-executed at baseline; 25 of 27 reproduced a nonzero divergence/failure count consistent with the finding's recorded evidence (exact figures in `S1.json`'s `seams[].note`). Two (`D2-s2-03`, and `D8-s1-02`'s full grid) exceeded this sweep's compute budget on a re-run (a real HA-loop solver grid; `objective_identities.py` and the full `D8/s1/matrix.py` run each take multiple minutes) — their seam_rule/threshold-pair was confirmed statically and their disposition rests on the judge-verified number, not an independent re-execution in this session.
4. **Null control / perturbation.** Every harness with a `--no-inject`/`--null`/`--disarmed`/flat-price arm was re-run in that arm too; all returned to 0 or to the finding's stated null-control number. Perturbations that are in-memory patches inside the harness (the majority) were re-run with their flag; perturbations that are a one-line production edit not exposed as a flag were not re-applied to a working tree in this sweep (that is `fixer.md`'s job) — the judge already recorded each one's observed value.
5. **Disposition.** All 27 cited findings dispose as `instance`: each is itself a verified (or judge-weakened-but-retained) occurrence of the class, and none of them turned out on re-reading to be `guarded` or `not applicable`. Widening surfaced additional call sites for 7 facts (D1-s2-51, D1-s2-91, D1-s3-01, D1-s3-02, D1-s5-52, D10-s1-01, D10-s1-02, D12-s2-01, D12-s2-02 — see notes below); those extra sites are folded into the same finding's disposition rather than counted as new findings, per `COMMON.md`'s "one finding per mechanism, however many places it shows."

## Barrier proposal

A pre-commit/CI lint pass (tools/audit/round9/D14/sweep/P2/enumerator.py --seams, generalising p2_facts.py's AST scan) that: (1) for each canonical predicate function named in a small registry (ThermalParameters.from_config, _dhw_enabled_from_config, wood_furnace_on, age_of, dt_util.parse_datetime, the fenced-call list in _apply_action/async_run_optimization, the entity-domain-from-target rule in pump_arbiter._write), extracts the CONF_ keys / attributes / thresholds it reads; (2) greps every other decision context in custom_components/heatpump_optimizer/*.py for a read of the same key/attribute/threshold outside the predicate's own body; (3) fails the check when a new such read appears without a call to the canonical predicate or an explicit '# P2: sibling of <predicate>, reviewed <date>' annotation. This converts the class from 'periodically re-discovered by audit' to 'caught the day the second call site is added'. Estimated gate cost: under 2 seconds (pure AST + regex, no solver, no real HA loop), so it can run on every PR touching custom_components/heatpump_optimizer/*.py, not just nightly.

## Limitations of this sweep

- This box did not have the round's pinned venvs (`venv314`, `venv`, `venv-r9`); every harness was re-run under plain `python3` after installing the missing packages the tracebacks named. No numeric divergence from the recorded evidence was observed in any harness that completed.
- `D2-s2-03` (`objective_identities.py`) and the full grid of `D8-s1-02`'s `matrix.py` did not complete inside this sweep's time budget (each is a multi-minute real-HA-loop solver run); their disposition rests on the seam_rule's static confirmation plus the judge's already-verified number, not an independent re-execution here.
- Widening was done fact-by-fact from each finding's own `seam_rule`, restricted to the files it names (as the finder scoped them), except for D14-s2-01 whose own detector is already package-wide. A fully package-wide AST widening for all 27 facts (the shape the proposed barrier implements) was not built in this sweep session; the barrier proposal above is scoped as future work, not as evidence already collected.
