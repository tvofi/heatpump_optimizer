_Requested by **tvofi**_

Round-9 F11.6: a fix review's `merge` verdict carries across a head move
that only merged main or added `ci:` commits, when the branch's own diff
is unchanged. Fixes #1667 (N-approval-rebuy). Part of #201.

Before: `tools/audit/app_approve.sh` approved only on `Fix review: merge
<sha>` naming the live head exactly. Every merge of main into a reviewed
branch therefore cost a full re-review. Round 9's window has 22 such
re-verification rounds, and none of them caught a defect (D13-s1-02).

After: a `merge` verdict at V is approved at a later head H when
`app_approve.sh --carry V H` holds. All three conditions must be true:
1. V is an ancestor of H.
2. Every first-parent commit in V..H is either a two-parent merge of a
   main commit whose tree is git's automatic merge of its parents
   (`git merge-tree --write-tree`, compared outside the merge-driver files
   below), or a single-parent `ci:` commit that changes nothing outside
   those driver files.
3. The branch's own diff against its merge base with main compares equal
   at V and at H.

The evidence gate then reads V. The posted review says the verdict was
carried (#1667), and the script prints a `CARRY` line naming the rule
that held. Any other move keeps today's re-review.
`fix-review.md` step 12 states the carry, and `web-fix-wave.js`'s
Reconcile prompt accepts a carried verdict at stage `merge`. Its merge prompt
is left alone: it is the shared `mergePrompt` fragment, canonical in
`web-fragments.md`, whose `files_tokens` cap has zero headroom. It also
runs straight after the wave's own review, so no head move can come
between the two.

**Deviation from card C18, chosen by tvofi (decision card in the project
thread, 2026-09-27T11:26Z: "Relaxed").** C18 said "byte-identical". Replayed over the window,
the literal byte rule carries 0 of the 22 rounds (Figures). Two things
move every such diff even when the branch's changes are untouched:
- Hunk headers shift when main adds lines above a hunk. That covers the
  line numbers and the function line git reads from above the hunk.
- The claim files and ledgers that stamps and CI bots rewrite on main
  (`tests/closures.json`, `*_budgets.json`) show up in the diff.

The branch implements the relaxed comparison instead: hunk headers and
`index` lines are dropped, and every file main's own `.gitattributes`
gives a merge driver is left out. Those files are graded at every head by
required checks (`closures`, `mutation`, the structure ratchet,
`budget-raise-gate`, golden drift). The attributes are read at main, never
at a head, so a branch cannot exclude its own file (self-test case). Every
added, removed and context line of every other hunk must still match byte
for byte.

- Fixture: a merge from main that changes one byte of the branch's hunk in
  its resolution is refused as a hand-resolved merge, while the same merge
  without that byte carries. A `ci:` commit that rewrites only a
  merge-driver file carries, and one that touches any other file is refused. The self-test at the merge base runs 119
  checks and the one at the head runs 146, 0 failed at both.
- Window: each round the rule carries is re-tested against a synthetic
  merge from main that appends one byte to a file in the branch's own
