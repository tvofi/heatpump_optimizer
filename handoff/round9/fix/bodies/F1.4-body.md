Why this change, and what it measures.

Four round-9 findings in the coordinator lane (roster group R9-F1.4), each
re-measured at merge base `8ff6827a` (origin/main, F1.3 merged as #1731 and
F5.2 as #1732) and at the head below, with the finders' harnesses from the
evidence export `79aa98ec` run at both ends:

- **D1-s2-52** (medium, N-restart, verified): five store writers do not wait
  for the startup read; a save in that window replaces persisted learned
  state. Survives at the merge base: `startup_clobber.py` lost=5 of 5.
- **D1-s2-53** (medium, N-restart, verified): `set_thermal_parameters`
  changes are silently lost at the next restart (24 of 26 fields).
  Survives: `runtime_params_restart.py` lost=24 of 26 changed.
- **D1-s2-54** (low, N-service-clamp, merged D6-s1-04, verified):
  `apply_manual_plan` accepts an `expires_at` past the horizon; the override
  owns all 96 steps unenforced. Survives: `manual_plan_expiry.py` 48 h arm
  free_at_apply=0/96, free_at_23h=0/96 (default control 16/96 and 96/96).
- **D1-s2-03** (medium, P1, verified): a sample count past int64 in the
  thermal-learning store fails every cycle, across restarts. Survives:
  `store_fuzz.py --sweep-huge --store thermal_learning` wedges 6 of 58 leaf
  values (cop_baseline "4"/"4:dhw" [1], capacity_envelope "-3" [1], each at
  1e20 and 1e308).

The change:

- **D1-s2-52**: `QuarantiningStore.async_save` now awaits its own
  `async_wait_for_read` before writing — the class-eliminating shape, not a
  per-writer discipline: no save the type can express clobbers its own
  pending read, for the five cycle writers, the manual plan, boost, away
  and the snapshots alike. `async_set_mode`'s and
  `async_reset_comfort_weight`'s explicit waits stay (they order the
  in-memory write against the load, which the save-side wait cannot).
- **D1-s2-53**: `async_update_thermal_params` writes the call's fields into
  the entry's options — `async_set_target_temperature`'s route; the options
  write reloads the entry (`async_update_options`), and the reload rebuilds
  the model from them.
- **D1-s2-54**: `build_override` clamps the expiry to
  `MANUAL_PLAN_WINDOW_HOURS` at the one constructor every apply goes
  through (both of the handler's construction sites), which makes README's
  "pins exact run slots for up to 20 hours" true of the service; and the
  manual-plan store's lead is set to the window, with `manual_plan` dropped
  from `tests/finite_boundary.py`'s `LEAD_OPT_OUTS` (the arm refuses a list
  that disagrees with the stores in either direction). A slot starting
  beyond the window is refused: it pins nothing and would come back
  clamped onto itself at the next restart, discarding the stored plan. A
  slot AT the expiry stays accepted-and-inert, the contract
  `tests/manual_plan.py` pins.
- **D1-s2-03**: `_async_load_thermal_learning`'s two count parses
  (cop_baseline, capacity_envelope) go through `_storable_sample_count`,
  which refuses a non-finite count or one beyond 2**31 — past int64
  `np.isfinite` raises, and that wedge survived every restart; the
  rejection flows through the loops' existing except, so no branch is
  added.

The N-restart class barrier this PR owes (RC2's, merged as #1641) is
extended in the same `tests/features.py` block RC2 landed: the two seams
the S5 sweep confirmed the merged barrier does not cover are checks there
now, and the class's `tools/audit/bugclasses.json` entry is set (detector,
barrier, status `barriered`).

Fixes #1662 (N-restart); Fixes #1681 (N-service-clamp); Part of #1647 (P1).
