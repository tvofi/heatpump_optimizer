## Mutation proof

**D4-s1-04, wiring** (`canvas.addEventListener("keydown", this.onKeyDown)`):
the fix review ran its own mutants against `tests/card.mjs` and found every
keyboard-route check passed with the listener removed, because each test
called `LayoutEditor.onKeyDown(...)` directly instead of going through the
real wiring. Tests now drive a real `canvas.dispatchEvent({type:"keydown",
...})`. With the `addEventListener` call removed:
```
FAIL  Enter on a focused pipe removes it, like a click would
FAIL  Delete on a focused pipe removes it too
FAIL  arrow keys move a focused box, cosmetic only
```
Restoring the listener, all of `tests/card.mjs` passes (see Figures).

**D4-s1-04, self-loop guard** (`pending === place` branch in `onKeyDown`):
with the branch disabled, pressing Enter twice on the same box drew a
self-loop edge (`addEdge` does not itself refuse `[p, p]`), and the old check
only asserted `kbConnectFrom === null`. The check now also asserts the edge
set is unchanged:
```
FAIL  pressing Enter on the armed box again cancels the connection
      edges drawn: heat_pump>buffer_tank, buffer_tank>mixing_valve, mixing_valve>upper_zone, buffer_tank>lower_zone, mixing_valve>mixing_valve
```
Restoring the guard, the check passes with no self-loop edge present.

**D4-s1-04, refocus in `refresh()`**: with the refocus logic removed, a real
`.focus()` → keyboard move → re-query round trip now fails, where the old
comment claimed focus was preserved but nothing read it back:
```
FAIL  and the redrawn box (a new element after refresh()'s innerHTML swap) holds it after
```
This needed `tests/dom_stub.mjs` extended with real per-shadow-root
`activeElement` tracking, `Node.prototype.contains()`, and a
`.class[attr="value"]` selector (production re-finds the focused element via
`.setup-box[data-place="..."]`) — the stub previously only tracked a single
global `document.activeElement`, so the round trip was untestable. Restoring
`refresh()`'s refocus, the check passes.

**D4-s1-04, connecting-state aria-label**: with the aria-label forced to the
"move" variant, the switch to the "connecting" variant is unpinned:
```
FAIL  the armed box's aria-label switches to the connecting state
```
`LayoutEditor.boxes` (the drag-positions array) carries no `.title` field —
only the internal render-time box objects do — so the check compares the
`L()` template's own static suffix text (everything after `{label}`) rather
than the interpolated label, which needs no box title. Restoring the
aria-label switch, the check passes.

**D5-s2-01** (stale `_private`-member comment references): unchanged from
this PR's prior submission; `Escape` disarm and the carry-in #1643 checks
