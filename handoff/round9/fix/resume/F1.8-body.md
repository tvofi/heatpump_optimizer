Round-9 fix group R9-F1.8: money figures carry the currency the price feed declares, grid-fee bounds scale with the currency, and the entry's unique id follows identity edits.

Before: a SEK instance reading a EUR price feed (Nord Pool or Tibber in EUR) labelled every money figure SEK/kWh, although the numbers were euros; nothing told the user. Platforms are built before the feed's first state, so even a coordinator that read the feed at setup stamped the instance currency on every sensor. The firewood price field was hard-labelled `SEK/m³` whatever the instance currency. The card resolved its money token in three places, and a `currency:` in the card config relabelled a figure the plan sensor had published in another currency. The grid-fee plausibility bound was a fixed 10 SEK/kWh: a legitimate 20 HUF/kWh fee (about 0.05 EUR) was refused in the options flow and raised the coordinator's fee notice. A reauth with a new token, an options edit of an identity slot, and `assign_entity` on an identity slot all rewrote the entry without re-deriving its unique id, so a second entry for the same installation was accepted and the true one refused (the finder measured 3 of each).

After: the displayed currency follows the price feed where it declares one, else the configured currency (mandate D6). `currency.declared_currency` reads the ISO code from the money half of the feed's unit, else an unambiguous symbol (`€`, `£`, `zł`), else the state's `currency` attribute; `kr` and a minor unit (`öre`, `ÖRE`) declare nothing. The coordinator adopts the feed's code at setup and again every cycle, so a feed that loads after the platforms is picked up by the next refresh; an unavailable feed keeps the last one. Every built sensor whose stamped unit starts with the old code publishes the new one. When the feed's code differs from the configured currency, one `price_currency` repair notice names both (translated `price_currency_mismatch`); an agreeing or silent feed clears it. The firewood, compressor-cost, fixed-fee and contract-price fields take the instance currency and a maximum scaled by `currency.money_scale`. `grid_fee.fee_bound(currency)` scales the 10 SEK/kWh bound the same way for the options page, its stated placeholder, `spec_problem` and the coordinator's notice. The card has one money resolver, `currency(own)`: the figure's own unit, then the plan's published `currency`, then the card config, then Home Assistant's. `config_flow.identity_update` re-derives the unique id from the merged data and options and returns it only when it moved and no other entry of the domain already holds it (the reconfigure step aborts on a held id; writing it would index two entries under one id, which real Home Assistant 2026.9.3 logs as an integration error). Reauth, the options save (both exits) and `assign_entity` write it with the entry.

The D6 rule's measured effect: the RCA replay (`p8_denomination.py`, under Figures) on a EUR feed reads `money_units_mismatched` 11 -> 0; the SEK null reads 0 -> 0.

As the roster carry directs, no "force everything through `resolve_currency`" metric is built; the RCA replay is the check.

How: adoption runs in `_update_current_state` (seam `core`), not in the fetch path, so `cut_fetch` does not grow. `self.currency` therefore has two writers, `__init__` (the initial value) and `_update_current_state` (per-cycle state), which is the one structure raise below. The sensor base stores the currency it was stamped with and swaps only a unit whose money half equals it, so non-money units and figures already in the feed's code are untouched. `money_scale` is a small table of units per SEK (HUF 50, ISK 20, JPY 20, KRW 200, CZK 5, and so on; 1 otherwise), used only for input ceilings and plausibility bounds, never to convert a figure. `identity_update` returns `{}` when the id is unchanged, so a close with no identity edit writes nothing, and an entry whose setup-time id predates a later-step identity slot is not restamped by an unrelated save.
