- **D8-s1-02** (class P2, `Part of #1644`): DHW Heating Schedule counted every
  15-minute step above 0.1 kW as a "heating period", while DHW Heating Plan
  merges consecutive steps above its own 0.05 kW threshold into one slot
  (coordinator `_plan_slots`) — one schedule published as two disagreeing
  counts. The schedule sensor now reads the plan's own slot list; a payload
  without a plan dict still answers, by merging the same contiguous runs at
  the same threshold. The fix is keyed on the mode, not unconditional: the
  #284 singular/plural fixtures pass at base and head.
- **D8-s3-03** (class N-dup-entity, `Fixes #1669`): Upper Floor Temperature
  has always published the indoor reading (the stated two-zone convention),
  so an enabled byte duplicate shipped on every install, single-zone ones
  included. It now ships disabled by default — the registry keeps existing
  entries' state, so no migration — and keeps its `source` attribute.
- **D8-s3-61** (class P2, `Part of #1644`): Valve Target Recommendation kept
  a static disabled default while its payload key exists only under a
  throttling mixing-valve mode — hidden from the installs that had the
  valve, available-but-unknown on installs with none. A sensor-local
  `_MixingValveGate` (the `ConfiguredInputMixin`/`DHWEntityMixin` shape)
  keys default and availability on `mixing_valve.is_throttling`. The gate
  lives in sensor.py beside its reader: entity.py is outside this PR's
  declared edit list.
