Fixes five stale-doc claims the round-9 D5/D6 finders measured (class I5,
part of #1645), and — from the F8.1 review — promotes the D5-s1 finder's
markdown-table-integrity harness into a permanent CI gate (class N-markdown,
#1674).

**Before:** README and docs/how-it-works.md named UI fields by labels the
options forms never show (`Inter-zone transfer`, `Radiator power fraction`,
`Floor return temperature`, `Solar forecast source`); README put the
two-zone split and the solar orientation factor on the wrong options page
(`Thermal model (expert)` / `Building type and emitters` instead of
`Two-zone model`); README's Heat Pump Action state list omitted two states
the sensor actually publishes (`idle`, `system_identification`); README's
disabled-by-default census assumed hot water is always configured, so it
missed six DHW entities a no-hot-water install also disables; and
how-it-works.md said the space solve runs from "two starting points" when
`_multi_start_minimize` scores four. Separately, the markdown-table-integrity
check the previous PR (#1696) used to find and fix a real GFM misrender
existed only as throwaway evidence tooling, needing a temporary
`npm install` — nothing kept it from recurring.

**After:** each of the five claims matches the production symbol the
finder read (`config_flow._OPTION_FIELDS`, the `strings.json`/`en.json`
labels, `HEAT_PUMP_ACTION_STATES`, a real `async_setup_entry` census on a
no-hot-water config entry, `optimizer._multi_start_minimize`), pinned by a
failing-test-first check in `tests/doc_claims.py` with a null control
reproducing the exact pre-fix shape. `tests/md_tables.mjs` now runs the same
GFM-table-integrity analysis offline, against the markdown-it 14.1.0 already
vendored for `render_md.mjs`, wired into the scoped gate via a measured
closure (no npm step, no new orphan file).
