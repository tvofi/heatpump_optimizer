## 2. Shape

```
contributor (fork)             our dispatch seat (our machine)              unchanged machinery
push head H; body; row   --->  ci.yml on H: early signal only
comment: Fix review: merge H
         review-commit: C --->  bus.sh adopt <pr> <comment id>
                                (A) git fetch origin main; outside.py, allowlist,
                                    CODEOWNERS, carry_audit.py, policy_lint.mjs,
                                    app_approve.sh read with git show origin/main:<path>;
                                    full contract over merge-base(origin/main,H)...H

                                    at H, or our machinery's under his mandate
                                    in force now, else refuse
```

**(A) Adoption is the authoritative gate.** .github/workflows/ci.yml:34-35 triggers on `pull_request`, so a fork head runs the workflow files of its own merge ref, and pr-contract's base pin is a step inside one of them (.github/workflows/pr-contract.yml:100-136). Green there proves nothing about a head that edited .github/. So the adopt subcommand, on our machine, first runs `git fetch origin main` itself (a stale local ref is an old contract), then materialises outside.py, the allowlist, .github/CODEOWNERS, tools/audit/carry_audit.py, policy_lint.mjs and app_approve.sh from `origin/main` with `git show` into a throwaway directory, never from the seat's checkout and never from the head, and runs the **whole** outside contract before `push_verdict`:
1. allowlist: the pull request's author and the comment's author match one entry by login, numeric id and type `User`, both read from the API;
2. the head repository's full name differs from ours (cross-repository), and the base is `main` of our repository (the train reads `baseRefName` only at admission, merge_train.py:4143);
3. the path rule (B) over `git diff --no-renames --name-only $(git merge-base origin/main H)...H`, three-dot, with H fetched from refs/pull/<pr>/head;

**Class O is the owner's approving review at the head, or his machinery's under his mandate (the ruling; round-2 point 2).** The owner's account (`OWNER_ID`, tools/policy/budget_raise_gate.py:89, read through `_is_owner`, :378) also approves from four programs, so "APPROVED by that id at H" alone says neither. outside.py takes that account's **latest** review on the pull request of any state (APPROVED, CHANGES_REQUESTED or DISMISSED, the set merge_train.py:2625 reads), so a later change request or dismissal voids an earlier approval, and admits it only when all four hold:
1. its state is APPROVED;
2. its body carries, on a line of its own, the outside-read line: the words "Outside read:" and a 40-hex commit L. L is H, or a commit from which H is reached by automatic merges of main only, decided by main's copy of `app_approve.sh --carry L H` (:741), which under (C) carries nothing else on a fork head; so one approval survives our own main merge;
3. the API's `commit_id` of that review is L, or H: GitHub re-anchors an approval's `commit_id` across a clean merge of the base (`raise_hold`'s docstring, merge_train.py:2388), so round 3's "the line equals `commit_id`" would have refused every approval after our own main merge. Disclosed correction, found while amending;
4. its body is exactly one of two forms, both read with the gate's own patterns, imported and never re-typed:
   - **the owner's own**: it matches neither `MANDATE_CITE` (budget_raise_gate.py:135) nor `AGENT_DECLARED` (:100);
   - **the machinery's**: it matches `AGENT_DECLARED`, `MANDATE_CITE` finds exactly one comment id in it, that mandate is in force **now**, and the owner's own latest decisive review (the ones not `AGENT_DECLARED`) is not CHANGES_REQUESTED, the rule `approval` keeps at :606-608: a mandate lets an agent approve, never overrule him.

**The mandate, read live as merge_pr.sh's owner mode reads it** (`mandate_in_force`, tools/audit/seat/merge_pr.sh:23-40): `_mandate(repo, id)` (budget_raise_gate.py:675) fetches the cited comment by id from the API and every record issue's comments since it; `mandate_state` (:423) is judged at the instant of the check, never at the review's submission and never from a copy in the tree. It holds only when the comment is on one of `RECORD_ISSUES` of our repository by its `issue_url` (`on_record_issue`, :126), was written by the pinned owner account, has `MANDATE_GRAMMAR` (:131) as its first line, was never edited, has its window open now, and no later comment by that account on either record issue revokes it. The covering set is `MANDATE_COVERS_POLICY` (:143), imported: `all` alone at the base. The brief's "scope all or policy" resolves to that constant, because the grammar has three scopes (code-owned, budget-raise, all) and none named policy; a policy scope added there later covers class O with no edit here, and `code-owned`, which licenses our own heads' code-owned paths, does not cover a contributor's grader change. An unread mandate, review list or thread refuses. The same read runs again wherever class O is read later ((E), `_approve`), so the owner's revocation is a kill switch until the merge.

**How the check tells the owner's machinery from a contributor, mechanically.** Three reads, none of which takes a byte the contributor writes as authority:
- **The account.** GitHub sets a review's `user` from the credential that posted it. `_is_owner` pins login, numeric id and type `User`. A contributor's token posts under the contributor's id, a fork run's `GITHUB_TOKEN` under the Actions bot's, and no secret reaches a fork run (Invariants). Who can post under the owner's account: the owner, and a seat on our machine driving his credentials (the gate's own statement, budget_raise_gate.py:91-99). Adoption and the class-O read execute nothing from the head (item 18), so fork code never runs where that credential is.
- **The mandate.** Read by id from the record issue as above. A pull-request body, a commit, a file, a branch name, and a comment by any other account or on any other issue or repository are not a mandate, whatever grammar they copy; an edit of the owner's comment by anyone with write access voids it.
- **The head.** Conditions 2 and 3, with (C) refusing every non-merge commit after L on a head that is not ours.

## 3. Alternatives

- **Trust pr-contract's base pin** (round 1). Lost: the pin is a step in a file the fork's merge ref supplies; one caller (CI) would hold a rule the bus must hold.
- **Fix tests.yml:1807 and add no adoption step.** Lost: the fix closes one site in one file; the next inline expansion of a contributor-named value is again a grader input with no path, and adoption is the one caller that sees every outside head.
- **Class O refuses a mandate-citing body and requires nothing** (the round-2 verdict's wording). Overruled as to the refusal by the ruling; the half that still loses is "requires nothing": of the bodies measured in (B) one is empty, and a test over free text with no required line fails open for every writer not yet written.
- **Call `approval` (budget_raise_gate.py:563) whole, as `policy_gate` does (merge_train.py:2313).** Lost: it drops a declared review that cites nothing before choosing the decisive one, so ci_probe.py's empty-bodied approval reads as the owner's own and is admitted; and it returns a verdict and a sentence, no handle on which review decided, so the line cannot be bound to it. outside.py imports its parts (`_is_owner`, the two patterns, `_mandate`, `mandate_state`, the covering constant) and re-types none.
- **Let the train's writers post the mandated approval on a fork head, as the ruling permits.** Lost: `_approve` and merge_pr.sh's owner mode post after the verdict and cite it as their basis, so the contributor's reviewer would be the only reader of the class-O diff and class O would be met by what a contributor's seat wrote.
- **Judge the mandate at the review's submission** (`mandate_check`, :474). Lost: a mandate revoked between the read and the merge would still admit; the train's policy stop judges at the merge for the same reason (merge_train.py:2299-2301).
- **Make each of the four writers refuse, and leave class O reading any review under the owner's account.** Lost: four call sites in three files must each remember, part 1 would be unsound until part 2 merges, and a fifth writer is admitted by default.
- **A base-graders CI job** restoring tests/ from the base. Lost: it says nothing of the lowered copy that merges, needs a second full run per push, and reports through fork-supplied workflow files.
- **Additions-only edits to test scripts, no read.** Lost: an appended early exit lowers a grader with no deleted line.
- **A CODEOWNERS line for tests/.** Lost: it would demand the owner's review on every pull request of ours; class O binds fork heads only, in the one module that knows them.
- **Add the contributor to `VERDICT_AUTHORS`, or issue a key.** Lost as in round 1: five readers assume one Bot id, and the evidence gate (app_approve.sh:563-661) wants a path on our machine.
