## 1. Partition rule (R1)

**Step A, a section's seam (N3's reading, stated):** the production modules a section references are those named by an import statement inside it, plus every name it loads that the script's imports bind to a production module (`case_select._aliases`); not transitive. `const`, `coordinator`, `__init__` are excluded. The seam holding most distinct modules wins; a tie goes to the first of inputs, model, plan, dhw, actuation, surface; none goes to cycle. The module-to-seam table is revision 1's, unchanged; a module it does not name is a refusal. Result: model 92, plan 48, inputs 37, cycle 29, surface 23, actuation 14, dhw 9; 73 ties, printed by the splitter. **No section ever joins another's part** (joins: 0), for the reason measured in step C.

**Step B, every edge typed.** An edge is (consumer, producer, name) where the consumer reads the name *free*, before any statement of its own binds it (a def body's globals count at the consumer's call). Each is one of:
- T1 import binding; T2 a constant (an assignment whose value contains no call); T3 a def or class no later section moves; T0 a process family the recording never moved;
- T4 a value bound by a call in a statement with no `R.check`, which no section between producer and consumer moves (static mutation or recorded name move);
- T5 state: a recorded module move, a static mutation (attribute/item store, in-place call, `setattr`), a recorded `@random`/`@syspath`/`@environ` move, a T4 candidate moved in between.

Counts at the base: T1 1284, T2 132, T3 303, T0 175, T4 216, T5 8817 (module-moved 8090, mutation 535, rng 171, syspath 15, environ 2, moved-between 4). Accounting of the table's 10241 `needs` edges, each pair at its strongest type: T5 8187, T1 381, T4 92, T3 40, T0 28, T2 13, and 1500 that are no free read (the table's reading counts a name the span binds before it reads it; the split-run null in section 5 is their control). Typed pairs the table lacks: 348 (the 4 unrecorded spans and moves recorded at this head); the splitter uses the union.

**Step C, placement, total and single-pass.** T1: the import goes into each consuming part's header. T2 and T3 whose free globals are all T1-T3: one copy in a helper module that runs no check (108 defs/classes and 46 constants cross a part). A T3 whose body reads a T4 name is copied into each consuming part instead. T4: the binding statement is copied ahead of the first consumer in each consuming part (79 bindings over 141 cross-part edges). **T5 must be intra-part.** Joining by T5 cannot settle: a union-find over T5 edges gives 3 components, the largest 250 of 252 sections (165 even without module moves), and any join rule converges to that. So the rule is **sever**: every cross-part T5 edge under step A is removed in the test source before the split (P0), and the splitter's `--check` refuses to write while one remains. No section can then need state built in two parts, because no cross-part state edge exists; the rule needs no tie-break beyond step A's.

**What P0 severs, measured.** Under step A, 7199 T5 edges cross parts, into 245 consumer sections. By the per-key recording, module moves are three families, not eight modules: the stub store (`homeassistant.helpers.storage` `_DISK`, `_VERSIONS`, `SAVE_COUNTS`; 72 producers), the coordinator's process worker (`_PROCESS_WORKER`, `_PROCESS_ATEXIT`, `_FENCED_CAUSES`, `_WORKER_FALLBACK_CAUSES`; 9), and off_restore's registries (`_CONSUMERS`, `_STALE`; 2). The rest (31 `added` keys: a package attribute set by a first submodule import, and `config_entries.HANDLERS`) are rebuilt by each part's own imports and are T1. Static mutation crosses on 53 names from 60 producers (`np`, `Coord`, `_coord_mod`, `boost_mod`, `DhwPlanner` lead), rng on 18 producers (2 seeders at the base, `_random.seed(7)` and `seed(11)`), syspath/environ on 5. These counts are an upper bound: an edge only matters if the consumer's checks change.

**Which edges are load-bearing: the swap run (the P0 instrument).** One `case_select.run` of the monolith in source order, with a span-boundary hook that keeps one copy of each T5 family per part and swaps the section's own part's copy in before it runs (the three module families, the class/module attributes static mutation names, `random`/`np.random` state, `os.environ`, `sys.path`). Each section then sees exactly the state its part alone would build, while T1-T4 names stay shared. A section whose `ok`/`FAIL` lines differ from the plain run is a load-bearing consumer; the swap run prints it with the family. P0 edits only those: a store or worker the section seeds itself, a patch restored in `try/finally` in its producer, a `random.seed(<k>)` at the head of a drawing section. Null: the swap run with one part (all sections mapped to one) prints no difference; perturbation: a hook that drops the swap for the stub store must list a section reading another section's save.

## 2. The splitter and its manifest (R3)

One committed instrument under `dev/audit/harnesses/` (closure-or-INERT classification is the fixer's): `--measure` prints section 1's tables; `--check` refuses a cross-part T5 edge, an unclassified module, a section missing from the manifest; `--write` writes the parts, the helper module and **the manifest**; `--classify` and `--port` are below.

**The manifest** is a committed JSON beside the parts: `{section id: {"part", "hash"}}`, `{shared name: "helper"}`, `{copied binding: [parts]}`. It is written once by `--write` and is from then on the only source of a section's part. `--port` and `--classify` keep every assignment in it; only a section id it lacks is classified, by step A, and only a T1-T4 edge the new text adds is placed by step C. A branch that adds a cross-part T5 edge is refused with the edge printed; the branch severs it. No global rule is re-run over existing sections, so a branch's hunk cannot move a section it did not write, and the ledger rows of existing sections keep their part.

**Port of an open branch.** The branch merges main's last pre-split commit (ordinary conflicts, its own), then `--port` regenerates the parts from its own tests/features.py under main's manifest, and adds manifest rows for its new sections only. Its tests/mutation_ledger rows naming tests/features.py are re-keyed by section 4 against those rows' sections. At the base 18 of 21 open pull requests edit tests/features.py (enumerator: `git diff --numstat $(git merge-base origin/main refs/pull/N/head) refs/pull/N/head -- tests/features.py` over the open list).

## 4. Mutation re-key and its cost (R4)

`killed_by` is script-granular, and `mutation_table.py killed` compares failing counts over a whole script run with no fail-fast. Measured per-part seconds (single core, recorder on, header 7.3 s included): plan 428.9, surface 234.2, model 222.8, cycle 112.8, actuation 80.7, inputs 21.4, dhw 19.2 (sum of spans 1069.0 on this seat; `tests/closures.json` records 1616.7 for CI, so CI figures scale by about 1.5). 4313 rows name tests/features.py. **A whole-part drive** of every row against every part whose sections' recorded `files` reach the row's production file costs 4820018 CPU-s: every file is reached by at least two parts, so file reach disambiguates nothing.

**The plan instead, by line reach.** A row's mutated lines are the lines of its anchor's file equal to its `old` text; a section reaches the row if the LINE run executed one of them; a part reaches it if one of its sections does or one of its copied T4 bindings' producers does. A line outside every function body (a module constant, a class body: 180 rows) runs once at import, under whichever section imported first, so it reaches every part with a section whose recorded `files` hold its module. At the base every row's `old` text matches at least one line; 556 rows are reached by one part, 3756 by several, 1 by none. The rule, in this order:
1. One reaching part: re-keyed to it with no drive. Sound given section 5's null (each section's lines in its part equal its lines in the monolith) and P0 (no cross-part state), because a mutant that only that part executes can change only its sections.
2. Several reaching parts: driven with `case_select run <part> --plan <reaching sections and their in-part needs>`, cheapest part first, stopping at the first kill.
3. None: driven against every part, cheapest first (code reached by subprocess or by a static read).
Cost: rule 1, none; rule 3, 1120 CPU-s; rule 2, 77925 CPU-s if the first candidate kills every row, 2304188 if every candidate part is driven. Both rule-2 figures are ceilings: the drive stops at the first failing check (a fail-fast hook in the splitter's drive around `case_select.run`; the baseline has zero failures, so a first FAIL is a kill). The fixer first drives a seeded 200-row sample of rule 2, prints its CPU-s and the share of rows the first candidate did not kill, and extrapolates; above 100000 CPU-s it reports to the orchestrator before the full drive. Shard plan: `mutation_table.py --shard K/N` over CI's mutation runners, N = 8 four-core shards give about 40 minutes of wall-clock for the 77925 CPU-s case. **A final regenerate re-drives only rows whose section changed part**: under the manifest that is a section the regenerate newly classified, so on an unchanged main it re-drives none and the step leaves the critical path.

## 5. Null controls

- **Test ids**: `PYTHONPATH=tests/hastub python3 tests/features.py | grep -E '^  (ok  |FAIL) ' | sort` at the base, twice, must diff empty before anything else (N2: 146 f-string check names, some value-bearing, e.g. features.py:3419); then the base against the concatenated parts' runs, empty, with each part's `ALL N` summing to the base's. Perturbation: drop one section from `--write`; the diff prints its lines.
- **Swap run** (section 1) is P0's control; **the split itself** is the swap run's: a section whose lines differ in its part but not in the swap run is a swap-hook miss, reported as a defect of the instrument.
- **Pins and kills**: `git diff --name-status $(git merge-base origin/main HEAD)...HEAD -- tests/mutation_ledger` lists only `M`, and filtered `grep '^[-+] ' | grep -v -e '"killed_by"' -e '"reason"'` prints nothing; per-script `killed_by` counts unchanged outside the parts, the parts summing to the base's. Perturbation: re-key one rule-1 row to a part that does not reach its line; a `--plan` drive of it must report not killed.

## Alternatives

- **Join instead of sever** (revision 1, and any union rule): measured to collapse to one part of 250 sections; it cannot meet the owner's per-seam split.
- **Partition by `needs` connectivity alone** (seams as components): the same one component.
- **Per-section scripts**: 252 scripts multiply `script_runs_*` by about 250 and pay the header per section.
- **Split by line range or title tag**: gives a new test no deterministic home (revision 1's reasons).
