### C. Session reads: loads, refusals with outcome, workflow runs
Measured in a designer transcript: a rule load is a line with `attachment.type` `nested_memory` and the `.claude/rules/<rule>.md` path (a Read under `dev/governance/` produced one; a Bash `sed` of the same file produced none); a Bash exit is a `tool_result` with `is_error: true` beginning `Exit code N`.
1. **Loads per rule:** `nested_memory` lines per path.
2. **[P1] Refusal, by the run's exit status, never by its wording.** A refusal is a run of a tracked file under `tools/` or `.claude/hooks/` that exits non-zero, at any code, or a PreToolUse hook denial, less four structural non-refusals, each its own scope row and never dropped: `usage` (exit 2, first output line begins `usage:`, argparse's form), `crash` (output holds `Traceback (most recent call last):`), `not-run` (126, 127), `killed` (124, above 128). Exit 2 is therefore a refusal unless its output has the usage form, which keeps round 1's R2 (`tools/pr/prepr.sh:1824` "REFUSE pr-body"). A call whose instrument is not the last simple command (a `| tail` included) prints `masked`, never a refusal or a zero.
   **Why text is not the predicate.** The wording is not uniform enough to be the predicate. Measured at the base with the literal enumerator `git grep -h -o -E "(echo|print|printf)[ (]+f?[\"'][^\"']*[Rr][Ee][Ff][Uu][Ss][^\"']*" 030a4d377f -- tools .claude/hooks`, each literal tested against `^\s*(?:[\w./-]+:\s*)?(?:REFUSE[DS]?|refusing)\b`. Refusals it misses, each exiting non-zero: `tools/audit/seat/bus.sh:563` "BUS refused %s %s: already posted" (return 1); `tools/audit/seat/roster_edit.py:1345` "roster_edit: LINT GATE REFUSED the push" (the refusal word is not first); `tools/audit/seat/cloud-setup.sh:97` "cloud-setup check: REFUSE" (a prefix with a space). The same literals also print lines that are not the instrument's own refusal ("the ledger refused ...", reporting another tool's), so a looser text rule over-counts. The exit status is the instrument's own statement that it said no; the text only annotates. Each refusal row carries its first output line matching `(?i)refus`, or `-` when there is none.
   **Exit 0 with a marker** is no refusal: the instrument let the run pass. Such runs print as a `marked at exit 0` scope row with their count (first token, after an optional prefix up to the first colon, `REFUSE[DS]?`), so a report-only instrument's refusals show rather than read 0. The round-2 `unmarked` row and marker set are retired: no instrument is classified by its text. No instrument is edited by this part.
3. **Outcome** of each refusal, from the next run of the same instrument in the session: `fix` (it passes, with an Edit, Write or commit between); `override` (it or a following `git push` carries a token of one literal OVERRIDES list, seeded by `git grep -n -E "ALLOW_|--force|--no-verify" -- .claude/hooks tools/pr`); `nothing` otherwise.
4. **Workflow runs:** one line per Workflow call: script, UTC time, notified status.
[c-subagent] The iterator walks each session's subagent transcript files as well as the session file, and prints `subagent files read k` beside `sessions read n` (local and cloud apart); a seat class it cannot read prints `NO-READ`. A subagent's refusal is its own row, outcome read within its own file.
**Lost:** a PostToolUse logging hook (a standing cost on every Bash call; a second record of the transcript; dies with a cloud container); a subcommand inside the token ledger's file (couples C's hot file to that group's; the card needs a nameable path [paths]).

### D. A cause per red run, in P7's vocabulary
[R1] The record is `roster_lib.convergence_why` and `loop_ledger.py` at part 2's head 28c3ba15ee; D owns its change there after part 2 merges. A red is a run attempt whose `gate` job (the job that reports gate.py's `REQUIRED` set) concluded `failure`, read from the job listing as `round_metrics.gate_conclusions` reads it, but per attempt rather than at the latest one. It counts on a pull-request head or on main's push (card E11-GATE-REDS asks the same record). Its cause is a `caused_by.cause` word already admitted, derived from the clearing event (prototype `dev/audit/rounds/round11/evaluation/gate_reds.py` on eval/r11 shows the match; nothing of its fetch is promoted):
- the PR's own later commit cleared it: `#<that PR>`;
- red at the merge base on main too: `#<n>`, the PR merged at main's first red push run of that context after its last green (merge-subject parse); unparsed: `unread`;
- a re-run at the same head went green, either a later attempt of the same run id or another run at the same `head_sha`: `external`.
No new cause word; `original` is not used by a derived row. **The one vocabulary change:** `convergence_why`'s cause test becomes a function the derived row calls too, and the rca rule is settled as: a derived row carries no `rca`, is never written to the roster, and never feeds `injected` (which stays the written, rca-backed rows), so the root-cause seat still owns every cause that counts as injected. `found_by`: `ci-main` on main rows; absent on PR-head rows, since a pre-merge red is no escape and P7's `found_by` counts escapes.
[P1-r3] **The reader is `round_metrics.py produce`'s directory; D adds no fetcher.** `fetch_runs` (`tools/audit/seat/round_metrics.py:391`) already pages `actions/workflows/ci.yml/runs` for every completed CI run since the open round's start, push and pull_request alike, and caches each run's job listing with `filter=all` under `jobs/jobs_<id>.json`. Every attempt's jobs are listed there with their `run_attempt`, so attempt 1 red then attempt 2 green reads with no `/attempts/<n>` call.
- **Change 1, in `fetch_runs`:** each `ci_runs.json` row keeps four more fields: `head_sha`, `event`, `head_branch`, and `pr`, the first `pull_requests[].number` or null. Each is read with `.get`, so an absent key is null and the existing fake paginator (`round_metrics_selftest.py:203`) stays valid. The existing keys `id, t, c, attempt` are unchanged. So are `runs.json` (the same dicts, filtered), `gate_conclusions`, `runner_s`, `product_green` and `restore`. Their self-test arms pass unedited, and that is the proof.
- `ci_runs.json` is rewritten whole each pass, so no cache migrates. The module docstring's INPUTS line and `instruments/round_metrics.py.md` name the four fields.
- **Change 2, in `loop_ledger.py`:** a new `--runs DIR` reads `ci_runs.json` and `jobs/jobs_<id>.json` from that directory. The PR match key is `pr`, else `head_branch` on a `pull_request` run whose `pr` is null. A red run with no jobs file, or with one cached at an older `attempt` (`runner_line`'s rule), gets cause `unread`; it is never dropped. With no `--runs`, the read prints `unread`. With `--runs` and no red, it prints 0.
- No API call enters `loop_ledger.py`. No file is added, so nothing new goes into `tests/closures.json`, CODEOWNERS or one-in-one-out. `tools/policy/field_coverage.mjs` names neither file at the base (`grep -n round_metrics tools/policy/field_coverage.mjs` prints nothing), so it needs no registration.
**Product/machinery** is not re-defined by paths: the column is R11-PRE-TOOLCHAIN-PIN's gate.py function (design/R11-PRE-TOOLCHAIN-PIN a37706d599, section 2) on the run's job listing; until it merges the column prints `unread`, and the failed job set prints as `machinery_line()` (`tools/ci/gate.py:293`) splits it today. `gate.py` is unchanged by D.
**Lost:** gate.py stamping a cause at run time (the clearing event does not exist yet; a guess and a second mechanism); four new cause words (a second vocabulary, R1); a second run fetcher (round 3's gate_runs.py: two caches of one listing that can disagree, a new file under one-in-one-out, and the `/attempts/<n>` call `filter=all` makes redundant).
