The class this PR closes is "a delete with no lease removes something that moved after the read, so a commit or tip made after the read is lost". Round 1 (`Fix review: blocked 7f95f9084b42aa5bd651a9aa98cc5b4292adcaaa`) closed it in `prune_refs.py` and closeout's local branches. Round 2 (`Fix review: blocked 35f063617944b17315333efe17bf46e73f4b16ef class-open`) closed it in worktree_gc's class A branch delete. Round 3 (`Fix review: blocked b195da4715d4b160e9e638d648e73603c7df59a4 class-open`, `verdict/3085`) found it open at the worktree removal itself. This re-cut closes it there:
- `worktree_gc.sh` `remove_worktree <wt> <head> [reason]`, the one removal both classes call: it deletes the worktree's own HEAD with the porcelain-read value as its old value, `git -C <wt> update-ref --no-deref -d HEAD <head>`. That is atomic in git's ref transaction, the same local lease as class A's branch delete. If HEAD moved (a seat committed after the read; for a detached worktree that HEAD is the only ref holding the commit), the lease refuses, the worktree is kept, `FAILED to remove worktree <wt>: its HEAD is no longer <head>, kept` is reported, and the class returns before the branch delete and the seat-scratch disposal. An empty head refuses. Once HEAD is gone no commit can land there, so the tree is deleted and its admin entry pruned (`git worktree prune`). `git worktree remove` cannot follow the lease, because it refuses a worktree with no HEAD (`validation failed ... is not a .git file`, measured). On a symbolic HEAD (class A), git compares the old value with the resolved branch tip, so a moved branch also refuses the removal (measured), and the branch itself is left to the round-2 lease.
- `closeout.py` step 3: `remove_worktree_leased(c, path, head)` uses the same mechanism, with `head` read from the same `worktree list --porcelain` block. A refused removal is kept as `moved-or-remove-failed`. The step's existing `git worktree prune` drops the admin entry.
- One seam: the leased local delete, `update-ref -d <ref> <old>`, is now the mechanism at every local delete site in this PR (closeout's branches and worktrees, worktree_gc's branch and worktree). `closeout.py` mirrors the shell function in Python, as `delete_local_branch` already mirrors class A's branch lease. It does not call into the shell script.
- Alternatives: re-reading HEAD just before `worktree remove` narrows the race but does not close it, as the verdict says. A worktree lock has no owner that a seat honours.
