The class this PR closes is "a delete with no lease removes something that moved after the read, so a commit or tip made after the read is lost". Earlier rounds closed it in `prune_refs.py`, closeout's local branches and worktrees, worktree_gc's class A branch delete and `remove_worktree` (classes A and B). The fix review at 5aae1e12 (`Fix review: blocked 5aae1e12ea1dea099edc87f94a914a33eabd1baf class-open`) found it open at class C, the orphaned-seat `rm -rf`. This round closes it there:
- `worktree_gc.sh` class C now reads the orphan's own HEAD once, right after the branch read, for both the attached and the detached arm (`ohead`). A wt that git reads as a checkout but whose HEAD does not resolve is kept as `unreadable-head`. Before the `rm -rf`, the removal deletes that HEAD with the value read: `git -C <wt> update-ref --no-deref -d HEAD "$ohead"`. That is the same atomic local lease `remove_worktree` uses. If a seat committed after the read, the lease refuses, `worktree_gc: FAILED to remove <seat>: its HEAD is no longer <sha>, kept` is reported, and the seat stays with its commit. On an attached HEAD, git compares the old value with the resolved branch tip, and deleting the symbolic HEAD leaves the branch ref itself in place (measured on git 2.43: stale old value refused, fresh one deletes `.git/HEAD`, `refs/heads/main` file untouched). For an orphan that is a worktree of another checkout, the branch therefore survives in that checkout. A wt that git cannot read as a checkout (the pruned class, `seat-orph-old` in the self-test) has no HEAD to hold a commit and goes unleased, as before.
- Alternatives: keeping every orphan whose wt is a git checkout would also close the race, but it re-opens the 9.5 GB class the instrument exists for, since every merged orphan is a git checkout. Re-reading HEAD just before `rm -rf` narrows the race and does not close it. The lease is the existing mechanism (`remove_worktree`), applied in the one place it was missing.
