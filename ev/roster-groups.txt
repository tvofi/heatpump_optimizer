brief: Owner request (tvofi, 2026-10-24), issue #2733: three routing invariants hold at every roster state. (1) Every carry not yet implemented routes to a roster group that is not done. (2) Every live roster group lists at least one issue in `issues` or `fixes`. (3) Every open issue but #201 is listed by at least one live roster group. Extend the instruments, add no script; size S, per the verifier (the verifier report filed on #2733, section 5). (a) roster_edit.py gains `mark-carry <group> <index|--match TEXT> implemented <sha>|moved <GROUP>|dismissed <reason>`; carry_audit.py gains an offline `roster` subcommand that REPORTS STRANDED = a pending carry on a done group; legacy carries (existing on done groups at the cut-over roster sha) are exempt, so there is no blanket migration and nothing is marked implemented by default. `[implemented: <sha>]` records that the sha is on main; it is not verification. (b) roster_sync sets the existing `carries-open` stage instead of `done` when pending carries remain; no set-stage refusal, so the factual sync at every merge is unchanged. (c) Invariant 2 is a brief_lint warning, not an error, so roster_edit's --push lint gate and fly-in registration at dispatch are not blocked. Invariant 3 is a tick report line in the default pass from the tick's cached issue list (CARRY made default and offline); the issue check is report-only on push, with no failing CI job on issues. (d) The offline `roster` check in governance.yml is scoped to PRs that touch the roster file or carry_audit and to push to main. Controls: a done group with a pending non-legacy carry reads STRANDED and its twin marked implemented at an ancestor sha does not; a live group with empty issues and fixes warns and stops warning once it gains one; an open issue listed only by a done group is reported and #201 is not; the null control is the first carry.
