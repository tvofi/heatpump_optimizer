# Scenarios this branch deliberately moves, one name per line, reason after
# the hash. env_drift.py prints their diffs but does not fail on them; a
# stale claim (a listed scenario that did not move) DOES fail, so entries
# cannot outlive the PR that needed them. It fails in its own right, under
# its own heading: nothing drifted, the list is just out of date. Empty
# list = this branch claims byte-identical behaviour everywhere.
#
# A claim describes exactly ONE diff and never carries forward. Two rules
# enforce that, and a branch must satisfy both:
#
#   1. The `claims-for:` line below is machine-read and MUST equal the
#      repo-root VERSION file. Both tests/env_drift.py (before any capture,
#      in either mode) and tests/entities.py fail when the two disagree.
#   2. In `--all` mode the list below must DIFFER from the baseline's --
#      the same names with the same reasons mean it was written for the
#      baseline's diff, not this one, and env_drift.py fails the run. The
#      stamp cannot catch that on its own: it only expires claims when
#      VERSION changes, and merges at an unchanged version are common here
#      (7b512bc, 401db6e and 2248f64 all sit at 4.0.0). An empty list is
#      always fine -- it claims nothing.
#
# So this file is rewritten by every change that touches it, and a release
# that moves no goldens still restates its own footprint: bump the line,
# leave the list empty. Without rule 1 the file is committed and inherited:
# v4.0.7, v4.2.0 and v4.3.0 each moved nothing, inherited the previous
# release's claims, and failed CI on main with N stale claims for code that
# was never wrong. Without rule 2 the same thing happens whenever two
# commits share a version.
#
# Two categories live in this file.
#
# A CLAIM is a bare scenario name with a reason after the hash. It asserts
# that THIS release moves that fixture, it is checked both ways (unclaimed
# drift fails, and so does a claim nothing matched), and it expires with the
# `claims-for:` stamp below.
#
# A MAY-DRIFT entry is a comment line, `# may-drift: <name> -- <reason>`. It
# asserts nothing: the fixture moved here, or it did not, and either is fine.
# It exists only for the five fixtures this gate itself declares
# non-reproducible across BLAS builds, and env_drift.py refuses any other
# name -- see `_may_drift` there for the full reasoning. Because it is a
# statement about those fixtures rather than about one release's diff, it
# does not expire with the stamp and is not part of the inherited-claims
# comparison.
#
# claims-for: 5.4.0
#
#
# v5.4.0 discounts the buffer tank's terminal credit by the fraction of
# stored heat the next window can actually spend. The discount is
# exp(-UA (cap - ambient) / (2 x hold demand)) with the tank's LEARNED
# standing-loss UA, and it applies to exactly one term in the objective:
# the buffer's entry in `_terminal_cost`.
#
# The footprint below is that scope, measured rather than asserted. Three
# scenarios move, and all three are valve + storage configurations -- the
# only ones where `buffer_is_store` is true and the tank therefore carries
# a terminal credit at all:
valve_storage              # tank credit discounted; the plan stores less at mild weather
valve_storage_flat_prices  # same, and the largest move: with no price spread the credit was most of the incentive
valve_storage_low_target   # same, at a lower comfort target
#
# What did NOT move is the load-bearing half of this claim:
#
#   * valve_storage_small_tank -- byte-identical. Below
#     BUFFER_STORE_MIN_VOLUME the tank is not a store, `_buffer_survival`
#     returns exactly 1.0, and the arithmetic is unchanged. This is the
#     empirical form of the "no-store paths stay byte-for-byte identical"
#     claim in the release notes; it is asserted in tests/features.py too,
#     but this fixture is the one that proves it end to end.
#   * every no-valve scenario, for the same reason.
#   * all five coord_* fixtures, config_flow, and the remaining 39 -- the
#     change touches no published key, no schema and no coordinator path.
#
# Winter is preserved by construction rather than by claim: the discount
# divides by the demand the stored heat is waiting on, so at -8 C it is
# 3.0% and the seasonal sweep in the release notes shows the coldest room
# temperature unchanged to the decimal. The three fixtures above sit at
# milder weather, which is where a 8-30% discount can change which plan
# wins.

# These five are the fixtures this gate declares non-reproducible across BLAS
# builds: each machine solves them to a different local optimum, so whether
# one differs from the committed recording is a fact about the runner, not
# about the diff. Unlike v5.1.9, this release CAN reach them -- every one is
# a valve or two-tank configuration carrying a buffer credit -- so their
# diffs mix a real effect with a machine artifact and cannot be separated
# fixture by fixture. That is exactly why they are unjudged rather than
# claimed: the three judged fixtures above carry the behavioural evidence,
# and none of these five is re-recorded.
