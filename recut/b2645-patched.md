R10-FLOW-TOOLKIT-MEASURE (Lean flow study, owner 2026-10-21; decision 0013: reusable instruments land in the tree). The study's measuring tools, generalised for any round: no round constant in code, the repository, roster, group prefix and window are arguments. Three instruments under `tools/audit/seat/`, each with `--self-test` on a recorded fixture, an `INSTRUMENTS.md` row and a step in governance.yml's `instrument-self-tests`:

1. `ci_critpath.py` (new). From one workflow run's job and step timestamps: each job's queue, duration and longest step, and the critical path (walk back from the job that ended last through the need that ended last). `needs:` are read from the run's own workflow file at its head SHA (git, else the contents API), never the tree's. A counterfactual holds every queue and duration fixed and replays the graph with `--drop-edge NEED:JOB`, `--delete-job JOB` and `--charge JOB=SECONDS` (a bare cost the caller states). `--workflow F --last N` prints median and p90 (nearest rank) over the last N concluded runs. API reads are paged (100), each run's jobs and each head's needs are cached per run id and head, and a run past `--max-reads` (default 200) refuses. It is the CI design archive's phase-2 method (tag `archive/probe/design-ci-rev4`, `measure/p2/critpath.py` and `c1_counterfactual.py`) generalised, not a second one: `dev/audit/harnesses/r10_critpath_archive_parity.py` runs the archive's own script and this tool over the archive's recorded jobs and requires every run's V1 gain to agree.
2. `review_strength.py` (landed by R10-FLOW-YIELD-PROBE; extended, not duplicated). Two changes. (a) The bus is now also read from the `archive/review/<pr>` and `archive/verdict/<pr>` tags `prune_refs.py` leaves: at the base the tool reads 103 verdicts and cannot reproduce the study's windows any more (0 PRs in the 0.52 window), here it reads 655 and reproduces 0.52 and 0.15 exactly. (b) The block classes the reviewer is taught are read from `--tree`'s `web-fix-wave.js` `VERDICT_CLASSES` literal (refusing a tree without one), never copied: the header prints the study's real-catch list split into taught real, taught bookkeeping and untaught real words, and `--by route` keys a block on the class the wave routes it to (its word when taught, else `other`, parseVerdict's rule).
3. `flow_metrics.py` (new). The study's section-0 enumerators over one window `[from, until)`, from git alone (the bus reader is review_strength's, the roster helpers roster_lib's): roster groups added and closed per hour, records' share of main's PR merges, first-pass yield of merged fix PRs on the bus, main absorbs per fix branch, merge-to-merge re-reviews of an unchanged PR diff (patch-id), and the share of whole hours with a merge. Each rule is in the file's header.

**Design choice, stated** (fixer.md step 11): `REAL_CATCH` stays the one list `review_strength.py` types. Which taught words name a catch is a judgement the vocabulary does not carry (`VERDICT_CLASSES` has no real/bookkeeping split), and ten of the study's sixteen real words are words reviewers wrote that the vocabulary never taught, so no reading of `VERDICT_CLASSES` can produce them. What is read rather than copied is the vocabulary itself: a class newly taught to `VERDICT_CLASSES` appears under `taught bookkeeping` until someone judges it, visibly, instead of silently.

Code-owned files touched: `.github/workflows/governance.yml` only (one added step). Every other file carries no code owner. Not run: nothing posts or pushes; `ci_critpath.py` only reads the API.
