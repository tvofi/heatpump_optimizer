The round-1 class is "a ref delete with no lease, deleting a ref that moved after the read". The repair closes it at every site in the two files its enumeration covers, prune_refs.py and closeout.py. It does not close it in their sibling `tools/audit/worktree_gc.sh`. This PR modifies that script (carry 4 adds the `unpushed` keep to class A), and closeout.py step 3 runs it as its final act ("a final worktree_gc").

In class A, `classify()` reads `unpushed_of "$wt"` (`rev-list --count HEAD --not --remotes`), runs `worktree remove --force`, and then runs `git branch -D "$branch"` (worktree_gc.sh:658). Neither delete is tied to the sha that was read. A seat that commits into that worktree between the unpushed read and the delete loses the commit. The `unpushed` keep that this PR adds as its guarantee therefore holds only for a branch that stays still. The body's enumeration rule names only the two files, and its dispositions treat `worktree remove --force` as "deletes no ref". That disposition fits closeout but not worktree_gc, which follows the remove with `branch -D`.

I reproduced it at this head with the shipped script on a real repo and bare remote (ev/wtgc-race.sh, ev/wtgc-race.txt). A `git` wrapper commits into the seat worktree just before `worktree remove`, the race arm. I tested a candidate fix on a copy (ev/wtgc-fix-candidate.txt). It replaces `git branch -D "$branch"` with `git update-ref -d "refs/heads/$branch" "$head"`, the same local lease closeout step 3 now uses, at the porcelain head the classifier read. The moved branch survives at its new tip, the script prints `FAILED to delete branch`, and `RESULT race=1 moved-tip-deleted-unpushed=0`. The null control still deletes, `race=0 ... =0`. The script's self-test uses a git stub, so the move arm needs the stub to answer `update-ref -d` with the old value, or a real-git case.
