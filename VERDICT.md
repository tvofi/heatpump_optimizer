## Revise point A — `draw_range.py:44-212` and `coordinator.py:5826-5861`: the store's feed is unnamed, and the only feed the note names books the next interval's ask and command.

The note says "ceiling-commanded running samples go beside the rolling window on the same `DrawRange`" and gives no other feed point. The one that exists is `draw_range.fold` / `observe` from `_record_accuracy` (`coordinator.py:5861`, fold at `9841`), which runs **after** `async_run_optimization` (`5826`, which runs `_run_system_identification` at `6217` and adopts its action at `10998-11009`) and `_apply_action` (`5845`, whose `pump_arbiter.apply` at `7558` has already written the new set-point). So for the interval that just ended, `_commanded_split` (`4695`) returns the **next** interval's action and `flow_command` the **next** interval's set-point, while `_measured_power` (`6453`) is the last interval's draw. One plan-level interval per run is therefore stored as a ceiling-commanded sample at p_max, and the last true ceiling interval is dropped (its draw pairs with the relax action).

Measured (`evidence/r3_probe_store.out`): a 2.0 h step (4 cycles) stores 4 samples, 3 at the real 3.0 kW and 1 at the plan's 1.5 kW; a 1.0 h step (2 cycles) stores 2, 1 true and 1 plan. Twelve samples are then three runs at 2.0 h (median 3.0, still right) but **six** runs at 1.0 h (median 2.25 kW for a 3.0 kW pump, 25 % low) — and 2.25 is below 0.85 × 5.0, so it passes `AGREE_TOLERANCE` and adopts a wrong top. The count is run-order dependent too: with a gate-held interval before the probe the plan sample is excluded (3 stored at 2.0 h, 1 at 1.0 h), so "twelve" is not a fixed number of runs. **Fix wanted:** state the feed point so an interval's draw pairs with that interval's ask and command (e.g. book from the step phase with the interval's own command, or fold before the next action is adopted); state the idle discrimination (`RUNNING_FLOOR_KW`, `_evidence`) the store inherits; and make the test assert the per-run count and values at both step lengths, not only that twelve samples set a top.

## Revise point B — `draw_range.py:162-172, 217-226, 438-469`: the store's median has no reader the note's evidence plan can assert, and the latch it claims to avoid is order-dependent.

Three limbs, all measured (`evidence/r3_probe_reader.out`):
- **The junction is not named.** `_metered_range` reads `observed()`, which reads `self.samples` only; the note never says how the separate store enters it. If the store is separate, nothing reads it: store-only with 12 samples gives `observed=(1.5, None)`, `planned=None`, `effective_max_kw=None`.
- **The reader it does name is gated.** `_metered_range` is called only from `planned` (`223`), which returns `None` unless `engaged` (`221`); `planned` only from `planned_range` (`455`), only from `diagnostics_view` (`469`). In the note's own F6 case that value is `None`. The Evidence plan's "eleven stored samples set no top, twelve do" therefore cannot pass as written: with twelve, `observed()`'s high is still `None` (needs 48, `draw_range.py:159`) and `effective_max_kw` is `None`.
- **If the samples also go through `observe`** — which §3's "The high of `observed` does take probe samples" asserts — **the latch is reachable**: 48 ceiling samples first on an empty window latch at append 48 and stay latched at 336 samples (share 0.143). The design both keeps the samples in the window and claims the separate store avoids the latch; it cannot be both.
**Fix wanted:** name the accessor (a store-level read, or a new `diagnostics_view` key that reaches the store without `engaged`), state whether probe samples are also folded into `self.samples`, state the latch's prefix condition and how a probe cannot trip it (or accept and test that it can), and make the test assert the accessor's value at eleven and twelve samples.
