## Findings

- The null drive's three "LOST KILL" rows come from stale bytecode, not from the skip. I re-ran the body's null-drive command (same seed and sample) at this head. It printed `NULL never rows driven 84: killed 3` and `NULL CONTROL: REFUTED or inconclusive`. These are the same three `tests/boost_drift_replay.py` pairs as the fixer's first pass, and all three fail one check: `an overlay beginning exactly now governs only the NEXT interval`. The cause is now established. `null_drive.py` writes a mutant into a worker tree, runs the driver, and writes the original back, and nothing suppresses bytecode. The positive control `boost.py:<module> CONST f0035934` (`BLOCK_HOURS = 2` -> `4`, the same byte size) runs `tests/block_duty.py` in under a second. When the mutant write and the restore fall in the same second, `boost.cpython-314.pyc` keeps the mutant's code, because its source mtime (whole seconds) and size both still match. Every later run on that tree then executes `_MAX_LEAD = 4 h`, which turns exactly that boundary check red. Reproduced: `ev/leak_same_second.txt` shows an UNMUTATED `boost_drift_replay.py` going rc=1 on that one check after a same-second restore, and `ev/leak.txt` is the control where the restore crossed a second and the run stayed green. Separately, 4 mutated and 4 unmutated traced re-drives of `price_model.py:543` were all green, and none executed line 543 (`ev/traced_mutant_price543.txt`, `ev/traced_unmutated.txt`). The PR's own `null_drive.py` therefore prints REFUTED or clean depending on sub-second timing. Main's lane `drive` in `tests/mutation_table.py` has the same write/run/restore hazard: a same-size mutant on a sub-second driver can leave mutated bytecode that kills later mutants on that worker tree, or turns a lazy baseline red. That is a lane determinism defect older than this PR, so I am not blocking on it. The fix belongs on the lane and the harness together (`PYTHONDONTWRITEBYTECODE=1` in `run_script`'s env, or dropping the file's `__pycache__` entry after each restore), with a failing test that plants a same-size CONST mutant on a sub-second driver.
