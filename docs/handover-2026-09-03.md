`--record` is not trustworthy enough to be mandatory:

- **#370** — cannot tell an improvement from a regression → **open**, `tvofi-claude-09` to take

Also decided: the direction check should **skip** `FRACTION_METRICS`, and #350 needs an
explicit category for metrics deliberately never re-recorded. `cross_seam_fraction` is the
only metric of 22 carrying both a tolerance band and a ratchet — **two mechanisms for one
job, and they disagree.** By structure, re-recording a tolerance metric can only ever
*loosen* the band: within tolerance it passes (nothing to record), outside it fails (a
decision). There is no case where it helps.

### The generalisations, stated as rules

- **A gate cannot be its own witness.** When the thing under test is the test-selection
  machinery, the selection that runs is chosen by the machinery being tested. #356 shipped
  a regression its own CI could not see, because editing a gate file routed it to the one
  path that could not reproduce the fault.
- **A check whose failure is *visible* and a check whose failure is *blocking* look
  identical in a passing run.** Both sessions built the first believing they had the
  second. Neither would have found it from a green log.
- **A figure quoted from another artefact is not measured until you have run the thing
  that produced it.** Three instances today, two mine (reading `golden.py`'s truncated
  "… and 8 more fields" as the whole set) and one carried between sessions (a `230` that
  counted a different population from the one it was used to describe — the real figure
  was 2).
- **A branch can be stale against main in a way invisible in its own diff.** Two shapes:
  a *move* PR reverting a fix that landed inside the moved lines (D6-03 nearly lost in
  #340), and a stale claim or budget table. Neither is catchable by reading the diff or
  re-running CI — only by comparing against current main.
