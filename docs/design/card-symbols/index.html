Setup page symbols — five prototypes

The owner's ask (2026-10-20): the setup page cannot show clearly when a wood coil is used; add a symbol for it and identify the existing box types with symbols. The configure buttons do not reach the right config pages. Five different mechanisms for the same surface, in the card's own tokens, light and dark, at 375 / 768 / 1280. Every prototype is one static, self-contained HTML file; the toggles at its top switch theme and coil state. The drawings below are the prototypes' own rendered SVG, not screenshots.

Box inventory — measured

8 boxes, 11 title strings, 1 visual style

Eight box() calls and eight places in describe_setup's present map (outdoor, heat_pump, wood_tank, mixing_valve, buffer_tank, dhw_tank, upper_zone, lower_zone) draw with one .setup-box style: nothing but the title distinguishes a tank from a valve. Four are always drawn; four are conditional. Three titles switch with the layout (buffer/heat-pump tank, mixing/4-way valve, house/upper floor).

Wood coil — measured

Needs five conditions

dhw_wood_coil_enabled + DHW + two zones + a throttling valve + a wood-tank probe. Today the only drawing is one ordinary pipe (wood_tank>dhw_tank, same class and stroke as every heating pipe) and one muted caption on the hot-water tank. The coil helix the docs still describe was removed by the re-design.

Configure — measured

Held constant across all five: the configure affordance

The folded block's one-line chip becomes a two-line button: Configure over the options page's own name ("Heating system and heat storage", "Hot water tank and inlet", "Sensors and entities", "Heat pump telemetry"). The page caption above the drawing states the path once:

Settings › Devices & services › Heatpump Optimizer › Configure › Advanced settings › the page named on the button

Home Assistant has no URL route into an options-flow step, so the card cannot open the page itself; naming it is what makes the button honest. The table below is the destination each control should reach.

Held constant: the coil state, in words

The hot-water box always carries two lines, in every concept and every state, so the symbol is never the only carrier and "configured but not modelled" is visible rather than silent:

  • Active — "refilled through a wood tank coil" / "preheats the mains water"
  • Configured, not modelled — "coil configured, not modelled" / "needs 2 zones, valve, probe"
  • No coil — "no hot-water coil" / "wood heat only"

Accessibility, measured on the rendered files

  • Text contrast (light / dark): title and rows 15.3 / 11.1; secondary ink 4.6 / 5.2; accent chip label 5.8 / 7.3. All pairs clear AA 4.5:1; the heat colour is used only as a graphic (3.7:1), never as text.
  • Drawn hit targets: 24 CSS px under a fine pointer, 44 px under a coarse one, by the card's own unitsPerPx rule; the HTML controls carry the same floor in CSS.
  • Every glyph is aria-hidden and every box is a role="group" whose name says the type and the coil state; every control is a real button with a spoken name and a focus ring.
