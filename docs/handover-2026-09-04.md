## The blocker: #387

`main` is red on roughly half of all merges, and the v6.3.12 stamp is blocked
behind it, because the stamp protocol requires the merge commit's own `fast` and
`closures` to be green.

The cause is a regression this programme introduced in #346 / PR #378, released
as **v6.3.11**. Every push to `main` forces `GATE_SCOPE=full` (by design —
`tests.yml` argues that the unscoped gate on main catches what a scoped PR gate
may miss), so `tests/stress.py` runs on every merge. Its coverage check demands
≥ 40 of 51 scenarios land in a *recorded* solver basin. Exactly 22 entries in
`tests/stress_budgets.json` carried an `alt_basins` list, and exactly those 22
flip together on a runner whose CPU model and BLAS kernels choose a different
multi-start basin — one cause, one cohort — leaving 51 − 22 = 29.

The floor of 40 was sized on the assumption stated in its own comment, that "a
third platform may hold a third basin **for some scenario**": per-scenario and
independent, eleven scenarios of slack. It is not independent. Four full-scope
pushes after #378 went 2 green, 2 red, on commits differing only in INERT paths
— so the code was identical and the runner was the variable.

**The owner chose the `env_drift` shape**: capture each scenario's solver work
twice in one run, tree and merge base, and compare computed against computed.
No basin table, no cross-machine assumption. Accepted cost ≈ +500 s on
full-scope runs only. Rejected: adding the observed basins to `alt_basins` (the
`ubuntu-latest` fleet is heterogeneous and not enumerable, so each new runner
model contributes another basin for all 22 and the table never closes), and
lowering or removing the floor (discards what #346 existed to buy).

**The owner also chose to fix #387 alone, before anything else merges.** That is
why the wave below is stopped rather than finished.

PR **#388** (`claude-web/fix-387`) carries the fix. If it has merged and `main`
is green, resume the wave. If it has not, finish it first — nothing else should
merge until `main` can be trusted.

## Traps this session hit, so the next one need not

1. **A killed agent never writes its own `state at stop:` comment.**
   Reconciliation is therefore the orchestrator's job on every resume: walk the
   `claude-web/*` branches and open PRs, and post the notes the dead agents
   owed. #372, #357 and #334 carry such notes, written after the fact.
2. **`MODE: SCOPED -- 0 script(s) run` and `MODE: FULL` both print zero.** They
   mean opposite things. Key on the mode line, never the count.
3. **A stale gate lock deadlocks the wave.** One was cleared today: its owner
   file named `pid=2063 shellpid=2079`, both dead, with no suite process
   anywhere and `load1` 0.31. The owner file records a pid precisely so a dead
   holder is a decidable fact rather than a judgement call — but clearing one
   you did not create still needs that evidence written down.
4. **A fixer can return prose in the `pr` field.** It satisfies the schema, and
   `!fix.pr` is false for a non-empty string, so a reviewer gets sent to a PR
   that does not exist. `web-fix-wave.js` now types `pr` as integer-or-null and
   checks `Number.isInteger`.
5. **Scheduled check-ins go stale faster than they fire.** Two fired today
   carrying instructions written before the state they described had changed.
   Rewrite the check-in's prompt whenever the plan moves, or delete it.
6. **One CI runner is not the fleet.** #387 exists because a property was
   measured on a single runner and generalised. The reviewer of #378 had asked
   exactly the right question — whether a 2× regression is still caught on a
   machine whose basins are not the recorded set — and the answer was taken from
   one sample.

## The egress proxy: what it permits, measured

Three observations, each from a real attempt, not from reading a policy:

| ref operation | result |
|---|---|
| `refs/heads` create or advance | **works** — every branch in this programme was pushed this way |
| `refs/tags` create | **403** on the `git-receive-pack` POST |
| `refs/heads` **delete** | **403** on the `git-receive-pack` POST |

The tag case is handled rather than worked around: #381 makes `stamp.py` report a
blocked tag push (exit 3, `RESULT stamped=vX tag_pushed=false`) instead of raising
a traceback over an already-public commit, and releases go through `release.yml`'s
`workflow_dispatch` path, which that workflow documents as being "for callers whose
push credentials are scoped to branches only".

The delete case has no such workaround and needs none: **branch cleanup simply
cannot be done from this container.** It is not a permissions question — a Bash
allow rule for `git push origin --delete *` clears the local classifier and the
push still returns 403 from the proxy — and it is not the GitHub token either. The
GitHub MCP server has `create_branch` and `list_branches` but no delete, so there
is no API route round it. Deletion has to happen from the owner's own machine or
the GitHub UI. Do not spend a session rediscovering this, and do not try to route
around the proxy.
