Round-9 fix F2.2, the solver lane's second PR. It takes five pieces of recomputed work out of the interpreter inside the solve. Every plan and every objective is unchanged: all 56 golden fixtures are byte-identical to the merge base.

- **D9-s1-01**. `_comfort_terms_batch` no longer loops over rows. It computes the whole batch in one pass, with the same expressions in the same order. Its per-row sums go through a new helper, `optimizer._row_sums`, which adds up a `[B, n]` batch in numpy's own pairwise order (eight interleaved partial sums, a fixed combine tree, halving above 128 columns) using only elementwise column additions. That makes every row byte-equal to the scalar sum on any backend and in either memory order, which is what `fixer.md` step 15 allows ("elementwise end to end"). The scalar `_comfort_terms` now calls the batch twin on a one-row batch, so the two agree by construction.
- **RC-sw1**. `cycling_penalty_batch` gets the same treatment, and `cycling_penalty` delegates to it.
- **D9-s1-02**. With a batch objective available, `_multi_start_minimize` and `_lbfgsb_restart` hand L-BFGS-B one fused value-and-gradient (`jac=True`). The point itself rides as row 0 of the finite-difference batch, so the scalar objective is no longer evaluated beside every gradient. Production still goes through `_batch_fd_gradient`, now with `f0=None`.
- **D9-s1-04**. The DHW min-run repair's feasibility check now extends the tank trajectory in chunks of 8 steps and stops at the first breach, instead of simulating the whole suffix before checking.
- **D9-s1-71**. `dhw_tank_heat_loss_coefficient`, `dhw_inlet_reference` and `effective_dhw_draw_pattern()` are memoised per `ThermalParameters` instance, keyed on their inputs, the same way `_buffer_ua_cache` already works. A changed input recomputes, and the draw pattern is returned as a copy.

This branch is rebuilt on main after #1711. `_comfort_terms` now delegates to `_comfort_terms_batch`, so #1711's `_floor_l1_scale` factor on the two-zone floor price lives in the batch twin, in the same expression order: `weight * (sum_u + sum_l) * (_COMFORT_FLOOR_L1 * self._floor_l1_scale)`. The continuation #1711 added still runs, and every golden is byte-identical to main.
