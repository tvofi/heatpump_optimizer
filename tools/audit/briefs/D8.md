# D8 — Sensor verification and ordering

Owner's brief: *"Sensor verification and ordering — every entity, constructed
against realistic coordinator payloads in each topology/feature combination,
publishes a sane, non-stale, correctly-typed value; no entity permanently
unknown where its data exists; grouping and naming such that alphabetical
sort clusters related entities; the enabled-by-default set is what a typical
user needs first."*

Read `COMMON.md` first.

## Method

1. **The matrix.** Topologies from `tests/golden.py:coordinator_scenarios()`
   crossed with feature toggles (DHW, two-zone, valve storage, two-tank,
   coil, wood, ECL110, PV, capacity tariff, grid fee, Tuya, away): build the
   coordinator the way `_capture_coordinator` does (inject prices and
   forecasts, run `_build_data_dict`), then construct every entity of every
   platform through the real `async_setup_entry` (`tests/entities.py:collect`).
   Run two cycles with changed inputs so staleness is observable.
2. **Per cell, per entity**: state, availability, `device_class`,
   `state_class`, unit, `entity_category`, `entity_registry_enabled_default`,
   attributes, `translation_key`, `entity_id`, icon. Checks: not
   `None`/`unknown` when the source key exists in the payload (map each
   entity to its source keys by reading its `native_value`); numeric where
   `MEASUREMENT`, tz-aware where `TIMESTAMP`, a listed option where `ENUM`;
   unit consistent with device class; attributes serialisable by `orjson`
   (no numpy scalars, no `NaN`); the value follows the payload between the
   two cycles.
3. **Ordering and naming.** Sort every `entity_id` and every display name;
   count the places where a family (DHW, tariff, learning, accuracy, ECL110,
   PV, card headline) is split by something else. Compare translations
   across `strings.json` and both languages.
4. **Enabled by default.** Derive a "first hour" list from what the README
   and the card need, compare with the enabled set, and list what is on
   that a typical user never reads and what is off that the card or the
   README relies on.
5. **The matrix graduates.** Write it so it can become a `tests/` script:
   deterministic, no network, one `RESULT` line per violation class.

## Reuse

`tests/entities.py` (`collect`, `DATA`, `display_name`, `_honest_coordinator`),
`tests/golden.py:_capture_coordinator`, `sensor.py` base classes.

## Traps

`HeatpumpOptimizerSensorBase.__init_subclass__` scrubs non-finite values for
every subclass. Leads that disappear when the harness is fixed are
non-findings with the harness gap named.
