## Findings

### D5-01 (medium, hygiene) — docs/img/marginal-cop.svg is stale: it plots marginal COP below the model's resistive floor

The committed `docs/img/marginal-cop.svg` is not what `docs/img/make_model_figures.py` regenerates from the shipped model. Its curves decode to marginal COP 0.888 (buffer, gate on) and 0.956 (DHW, gate off) at −20 °C, where the shipped model returns 1.0 for both (`_cop_law`'s `max(cop, 1.0)`, `compute_cop_dhw`'s `max(base_cop * dhw_penalty, 1.0)`). The generator draws by calling `ThermalModel.marginal_cop` directly and `docs/` is INERT in `tests/closure.py`, so nothing re-runs it; the generator's own docstring ("a figure cannot go on illustrating a claim the model has stopped making") is falsified by this figure.

- Evidence: `figures_fresh.py` — `RESULT stale=1` (of 3 figures checked; the other two are byte-identical).
- instrumented_symbol: `thermal_model:ThermalModel.marginal_cop`.
- Perturbation: scale the standby-loss term in `simulate_dhw_step` by 1.5 → `stale` 1 → 3 (all three figures); file restored byte-identically.
- metric: number of the 3 committed docs/img model SVGs whose regenerated bytes differ from the committed file.
- proposed fix: re-run the generator and commit the regenerated `marginal-cop.svg`; note in the docstring that this is a manual step (docs/ is INERT).

### D5-02 (low, hygiene) — README's Documentation index omits docs/automations.md, a page the README itself cites

README.md's `## Documentation` table names 8 rows but omits `docs/automations.md`, a reader-facing page the README links four times in its own prose.

- Evidence: `readme_index.py` — `RESULT index_gap=1`.
- Perturbation: delete the `docs/architecture.md` row → `index_gap` 1 → 2; README restored byte-identically.
- metric: number of existing docs/*.md pages linked from README outside its Documentation table and named by no row (excluding docs/plan-*.md and docs/HANDOVER.md).
- proposed fix: add one row pointing at `docs/automations.md`.
