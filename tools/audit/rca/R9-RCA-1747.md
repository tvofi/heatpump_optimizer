# RCA-1747: the co-optimisation replan dropped the DHW mode block (R9-EG-B8)

Root-cause seat for issue **#1747**, run beside the fix and not inside it
(`tools/audit/briefs/root-cause.md`, `.claude/rules/defect-root-cause.md`). The
fix is R9-EG-B8, PR #1786, merged at `830f84ad`. The fixer's draft (resume note
on `handoff/r9-eg-b8-v2`, `b6eb9188`) and the fix reviewer's two corrections

(the pins of `tests/requirements-ci.txt`; the interpreter is not CI's), 1 BLAS
thread. The instruments and their outputs are in `tools/audit/round9/rca/1747/`
on this branch. Each is run from the repository root with

Trigger: 1 of `defect-root-cause.md`. The defect shipped in every tag from
`v5.3.0` to `v6.7.12`, which is 94 tags (`git tag --contains 64a54195`, filtered

## Root cause

### Reproduction

`b8_replan_blocked.py` (the finder's probe, sha1 `e29cc879`) at `754d2319`
(main at v6.7.12, the fix's merge base), wood_coil, `dhw_blocked=True`:

```
as-is    delta=-2.0 negative_steps=68/96 shipped_dhw_kwh=9.22 dhw_steps=16 dhw_floor_breach_c=0.629 build_calls_blocked_arg=[True, '<omitted>']
as-is    delta=-3.0 negative_steps=96/96 shipped_dhw_kwh=8.63 dhw_steps=13 dhw_floor_breach_c=0.04 build_calls_blocked_arg=[True, '<omitted>']
control  delta=-2.0 negative_steps=68/96 shipped_dhw_kwh=0.00 dhw_steps=0 dhw_floor_breach_c=20.81 build_calls_blocked_arg=[True, '<omitted>']
```

At shifts 0.0 and -1.0 both arms ship nothing. The replan is still built there,
because the spy records `'<omitted>'` in the second build at every shift, but it
is not adopted. Full output: `probe_base_754d2319.txt`.

### Cause

`HeatPumpOptimizer._build_dhw_requirements` is called from two sites: the first
DHW build in `_optimize_with_dhw`, and the replan in `_co_optimize`. Its
`blocked` keyword defaults to `False`, so a call that omits it means "not
blocked", and nothing raises. v5.3.0 (`64a54195`, #80, 2026-08-28) threaded
`blocked=h.dhw_blocked` into the first build only. The replan already existed
before the block did: it was extracted as `_co_optimize` in `c1b53971`
(2026-08-22).

Which side moved was checked with `git log -S`, not taken from the error text:
- `blocked=dhw_blocked` first appears in `64a54195`;
- `def _co_optimize` first appears in `c1b53971`, six days earlier;
- between `64a54195` and `754d2319`, `git log -G'_build_dhw_requirements\(|blocked='`
  on `optimizer.py` returns two commits, `4a7bdb69` (2026-09-03) and `5ec32572`
  (2026-09-09). Both split the builder. Neither touches the replan's arguments.

So the new keyword reached an old sibling's caller at one site and not the
other. The feature did not create a second call site. v5.3.0's commit message
names the DHW paths it covered: "the LP, the greedy pass and the floor repair
all plan around it". That enumeration was written by hand, and the replan is not
in it.

The same commit did thread the block into a sibling at the coordinator level.
The what-if solve's `min_temp_floors` call is followed by the comment "v5.3.0:
and the mode block, for the same reason as every inherited input above". The
sibling it missed was inside `optimizer.py`, where no enumeration was attempted.

### Process state: (c)

The process is v5.3.0's own suppression tests in `tests/features.py`, section
"v5.3.0 — a blocked channel is suppressed, and visibly so". They exist
specifically for this property. The check "a heating-only mode plans no hot
water at all" asserts `max(_mb_dhw.dhw_power_schedule) == 0.0` on the published
plan, which is exactly what #1747 violates. The fixture carries its own reach
control against vacuity: "a suppression test against a plan that was empty
anyway proves nothing". It has run on every gate since `64a54195`, and every
run was green.

- **The process existed.** A check for the violated property was in the suite.
  So this is not (a). The fixer's draft recorded (a) on "no process compares the
  call sites of one builder". That is a missing proxy, not a missing check for
  the property. `root-cause.md` §2: "'Nobody checked X' is state (a) only if no
  check for X existed."
- **It was followed.** The tests were written with a control, and they run on
  every gate.
- **It did not produce the intended result.** The check asserts the property
  on the published plan. A dropped block in the replan reaches the published
  plan only when the replan is adopted, and it is adopted only when its
  candidate scores better. At positive prices it never does.
  `rca_suite_reach.py` runs a whole test script with pass-through spies and
  counts, for solves with and without a DHW block:
  - `optimize` calls;
  - `_co_optimize` entries;
  - replan builds;
  - adopted replans and the DHW energy they carried.

  The vacuity control checks that the first build competes for capacity ("the
  space plan may re-arrange, because the compressor is no longer shared"). It
  does not check that the replan runs, or wins.

This is (c) and not (b), because nothing was disobeyed. A firmer "test the
blocked path" would change nothing: the blocked path was tested, and its
fixture was chosen with a control. It is not (d) either. The replan was already
there when the tests were written, so no precondition changed underneath them.

`fixer.md` step 8 (sibling enumeration) is not the process here. It was added on
2026-09-22 (`6bc932db`, #1414), 25 days after v5.3.0, and it binds fixes. No fix
touched either build's arguments after it existed (the `git log -G` above), so
it was never invoked on this seam. The class-level process, the P2 barrier, is
recorded as (c) by `tools/audit/rca/R9-P2.md` and is scheduled for R9-F1.11. It
is not re-derived here.

### The fix's own census repeats the (c) shape

EG-B8 added two checks on the golden wood_coil fixture at -2.0:
- "a DHW-blocked plan ships no hot water when mostly negative prices tempt the
  co-optimisation replan (#1747)", an output check;
- "and every DHW build that solve made was told the mode is blocked", an input
  census. It spies on `_build_dhw_requirements` and asserts
  `len(args) >= 1 and all(args)`.

The census is the stronger check. It sees an omitted block whether or not the
replan wins. But it does not assert that it saw the replan at all.
`rca_census_reach.py` replays its fixture and evaluates both predicates
verbatim under three arms. At EG-B8's code head `1b43198e`:

```
arm=as-is     builds_seen=[True, True] shipped_dhw_kwh=0.00 breach=20.810 check_first=pass check_companion=pass companion_with_reach(>=2)=pass
arm=no-replan builds_seen=[True]       shipped_dhw_kwh=0.00 breach=20.810 check_first=pass check_companion=pass companion_with_reach(>=2)=FAIL
arm=off-spy   builds_seen=[True]       shipped_dhw_kwh=9.22 breach=0.629  check_first=FAIL check_companion=pass companion_with_reach(>=2)=FAIL
```

At `754d2319` the as-is arm reads `[True, False]`, and every predicate fails.
So on the route that existed, the census does detect the defect.

In `off-spy`, the replan rebuilds through a callable the spy does not patch and
drops the block. That is the #1747 defect again, on a new route, for example
the planner call EG-B5 will turn this site into. The census passes. Only the
output check fails, and only because this fixture's price shift makes the
replan win. The reach clause fails in both perturbed arms and passes as-is.
That is the P2 RCA's (d) countermeasure, "the census asserts its own
preconditions", applied to this fact.

### How far the class reaches

**Class: P2** (`tools/audit/bugclasses.json`): "One fact decided twice by
divergent predicates: a guard at one seam, missing at its sibling". Here the
guard is the DHW mode block, and the two seams are two builds of one plan.

The fixer's draft counted "1 instance of a defaulted keyword omitted at a
second call site". That measures a narrower syntactic sub-shape of P2. P2 itself
has 66 instances over rounds 1–9, 27 of them in round 9, with status `open`, a
null detector and a null barrier. Its barrier is owned by R9-F1.11
(`rca_planned`). #1747 is not in the register, because it came from the EG-B5
design seats and not from a judged audit finding. It belongs under P2's
`non_round_instances`.

Class search with the sub-shape's instrument, `kwarg_seams.py` (the fixer's,
sha1 `25ec2ea2`). It reports each `self.<m>(...)` called from two or more sites
in one module, where a keyword `m` defaults is passed at one site and omitted at
another. It was run over every `custom_components/heatpump_optimizer/*.py`
(67 files):

| ref | seams | of which #1747 |
|---|---|---|
| `64a54195` (v5.3.0) | 19 | 1 |
| `754d2319` (fix base) | 63 | 1 |
| `1b43198e` (fix code head) | 62 | 0 |

Disposition of the 62 at the fix's head, read by this seat except where noted:
- `optimizer.py` (10): the fixer's dispositions in #1786's body. They were
  re-read and hold. Examples: `space_demand` omitted at the first build by
  design, and the `_build_result`, `_compute_baseline_power`,
  `_deferred_energy_cost` and `_settlement_caps` omissions in the space-only

- `coordinator.py` (7):
  - `_mold_floor_series` without `target_cap` in the live solve. By design: its
    docstring caps at the configured target, and only what-if solves pass it.
  - `_plan_slots` without `reasons`/`other_powers` (4). In the what-if summary
    only `len()` of the result is read, and neither keyword changes the slot
    count.
  - `_tibber_fetch_failed` without `exc_info` (2). A logging choice.
- `thermal_model.py` (6):
  - `_simulate_step_single` without `_cop`/`_q_solar`/`_u_eff` (3). By design:
    the `n_sub == 1` path computes them inside; they are precomputed only for

  - `compute_cop` without `flow_temp` (3). The space flow is the default; the
    buffer store passes its own.
- `config_flow.py` (39): `async_show_form` without `description_placeholders`

So the instrument's precision on this tree is 1 defect in 63 seams at the base.
Nothing else it returns is a second instance.

## Cost test

`cost(countermeasure, recurring) < cost(defect) x P(recurrence)`, wall-clock
per round (one audit round and its fix wave).

**cost(defect), measured from session and PR timestamps.**
- EG-B8 fixer seat: 14:02:34Z to 15:24:28Z, 82 min.
- Fix review: 15:28:32Z to 16:07:29Z, 39 min.
- Total: **121 min**. PR #1786 was open 42 min (15:26:40Z to 16:09:09Z) inside
  that window.

This is not split from the F9.3 carry (the `normalize_profile` projection),
which rode the same PR, so it overstates #1747 alone. It excludes the mapping,
skeptic and review seats that found the defect, and this seat.

**P(recurrence).**
- The class: P2 has 66 instances in 9 rounds (mean 7.3 per round), and 27 in
  round 9 (`bugclasses.json`).
- The sub-shape: 1 known instance in 9 rounds (#1747). That is an estimate from
  the absence of any other among the 63 seams above, plus the register.

**Options.**

1. **A standalone `kwarg_seams.py` check** (the fixer's candidate).
   - Standing cost: 3.2, 3.6 and 3.4 s over three runs across the 67 modules,
     at load average about 2 on 4 cores.
   - At R9-P2.md's assumed 41 PRs × 3 gate runs per round, that is 418 s, about
     **7.0 min per round**.
   - It also needs 62 disposition rows at landing, and a new row for every
     legitimate seam after that.
   - Right side for its sub-shape: 121 min × 1/9 ≈ **13.4 min per round**.
     It passes by 1.9×, on an estimated P, at a precision of 1 in 63.
   - It would also be a second check guarding a P2 fact outside the P2
     registry. R9-P2.md refused that shape: "so that one shape is not guarded
     by two checks".
2. **A reach clause on EG-B8's census.** One comparison in an existing check,
   so the standing cost is **≈ 0**. It fails on the two routes the census
   misses (the `off-spy` and `no-replan` arms above) and passes on the fixed
   tree.

**Verdict.** P2 is an audit class (27 instances in round 9, at least 3), so a
barrier is owed whatever the test says (`defect-root-cause.md`, the audit-class
exception). The test picks its form: option 2, 0 against 13.4 min per round,
landed inside the P2 barrier. This seat builds no standalone check.
`kwarg_seams.py` goes to the barrier's owner as a candidate registry shape,
with its measured precision, and not as a gate.

## Countermeasure

This maps to the (c) finding: a check that was obeyed and ran green because its
fixture did not reach the path. The countermeasure makes the check assert its
own reach, rather than instructing anyone harder.

- **Carried to R9-F1.11**, the P2 barrier: `.claude/workflows/carry-1644.json`,
  its fourth carry (`brief_lint.mjs` labels it `carry 3`).
  - Name EG-B8's census as the P2 registry's holder for this fact.
  - Give it the reach clause, demonstrated as above.
  - Add #1747 to P2's `non_round_instances`.
  - `kwarg_seams.py` is offered as a shape, with the 62 dispositions above.
    Its key must not be able to silence the replan's own call (`fixer.md`
    step 14).
- **Carried to R9-EG-B5**, which turns the replan into a planner call:
  `.claude/workflows/carry-1743.json`, its second carry (`carry 1`). Re-point the spy at the
  callable the planner uses, and keep the reach clause, so the census refuses
  rather than passes if it loses the replan.
- **Policy: none new.** The clause "a census asserts its own preconditions" is
  already drafted by R9-P2.md for `fixer.md` step 8. It waits on tvofi's
  approval under F11.5. #1747 is a second worked example for that draft: a
  control that proved the fixture non-empty for one build, while the defect
  lived in the other.

The roster briefs of R9-F1.11 and R9-EG-B5 on `handoff/audit-r9-fixplan` carry
the same text (`finding-propagation.md`: both copies). Where the two disagree,
the newer one is right.
