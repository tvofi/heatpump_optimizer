# RCA-1747: the co-optimisation replan dropped the DHW mode block (R9-EG-B8)

Root-cause seat for issue **#1747**. It ran beside the fix and not inside it
(`tools/audit/briefs/root-cause.md`, `.claude/rules/defect-root-cause.md`). The
fix is R9-EG-B8, PR #1786, merged at `830f84ad`.

Two drafts were read as hypotheses and re-measured here: the fixer's (resume
note on `handoff/r9-eg-b8-v2`, `b6eb9188`) and the fix reviewer's two
corrections (`EG-B8-review-974c805c/VERDICT.md`). Both place the defect at
v5.3.0. The history below corrects that. The omission entered at v5.3.0, but
it was unreachable there. It became live at `81aa0c3b` (#470). So the process
state is **(d)**: neither the draft's (a) nor the reviewer's (c). The class
correction (P2, not a frequency-1 narrow class) is the reviewer's, and it is
kept.

Measured on a Linux cloud box with CPython 3.11.15, numpy 2.4.6 and scipy
1.17.1 (the pins of `tests/requirements-ci.txt`, on an interpreter that is not
CI's), with 1 BLAS thread. The instruments and their outputs are in

### Cause

`HeatPumpOptimizer._build_dhw_requirements` has two call sites:
- the first DHW build, in `_optimize_with_dhw`;
- the replan, in `_co_optimize`.

Its `blocked` keyword defaults to `False`. So a call that omits it means "not
blocked", and nothing raises.

Three commits, each checked with `git log -S`/`-G` rather than read from the
error text:

1. **`c1b53971` (2026-08-22)** extracts the replan as `_co_optimize`. Its only
   trigger is `pinned = (dhw_power > 1e-6) & (space_power >= headroom - 1e-3)`:
   it replans only where the first DHW plan draws power.
2. **`64a54195` (v5.3.0, #80, 2026-08-28)** threads `blocked=h.dhw_blocked`
   into the first build only. A blocked first build plans no DHW power, so
   `pinned` is empty and `_co_optimize` returns before it builds anything. The
   omission is **unreachable**:
   - `894b3310` builds once, whatever the price;
   - `rca_suite_reach.py` over `tests/features.py` at `64a54195` counts 2
     blocked solves, 2 `_co_optimize` entries, and 0 replan builds;
   - v5.3.0's commit message lists the DHW paths the block covers: "the LP,
     the greedy pass and the floor repair all plan around it". Under that
     trigger, the list was complete.
3. **`81aa0c3b` (#470, round-3 fix 3L-G1 for #400, 2026-09-06)** credits the
   wood-tank refill coil. It adds a second trigger to the same guard,
   `if not bool(np.any(pinned)) and not coil_replan:`. `coil_replan` fires
   whenever the wood forecast changes the priced draws, and it does not
   depend on the first plan's DHW power. A blocked plan with a wood coil now
   reaches the replan build, and that build still omits the block.

`rca_coil_trigger.py` at `754d2319` isolates the route. In every arm, the
first plan's peak DHW power, as `_co_optimize` receives it, is `0.0`.

```
arm=as-is   delta=-2.0 builds=[True, '<omitted>'] shipped_dhw_kwh=9.22 breach=0.629
arm=no-coil delta=-2.0 builds=[True]              shipped_dhw_kwh=0.00 breach=20.81
arm=no-coil delta=-3.0 builds=[True]              shipped_dhw_kwh=0.00 breach=20.81
```

With the coil forecast suppressed, the replan is never built under a block. So
the coil trigger is the only route by which the omitted keyword reaches a plan.

Between `64a54195` and `754d2319`, `git log -G'_build_dhw_requirements\(|blocked='`
on `optimizer.py` returns `4a7bdb69` and `5ec32572`. Both split the builder,
and neither touches the replan's arguments. `81aa0c3b` did not touch them
either: it changed the guard above them.

### Process state: (d)

`root-cause.md` §2 names four states. Each was tested against the evidence:

- **Not (a).** A check for the violated property existed. `tests/features.py`,
  "v5.3.0 — a blocked channel is suppressed, and visibly so", asserts "a
  heating-only mode plans no hot water at all"
  (`max(_mb_dhw.dhw_power_schedule) == 0.0`) on the published plan. It has run
  green on every gate since `64a54195`.
  - The fixer's draft recorded (a) on "no process compares the call sites of
    one builder". That is a missing proxy, not a missing check for the
    property.
  - `fixer.md` step 8 (sibling enumeration, `6bc932db`, 2026-09-22) came after
    both commits and binds fixes. Nothing crossed this seam after it existed.
- **Not (c).** The reviewer read the v5.3.0 checks as followed but
  unsuccessful, because their fixture never reached the replan. The fixture
  could not reach it, because at `64a54195` no blocked solve could. The
  checks covered every route that then existed from a DHW block to a
  published DHW plan. The fixture's own control ("a suppression test against a
  plan that was empty anyway proves nothing") was the right control for those
  routes.
- **Not (b).** Nothing was disobeyed at either commit.
- **(d): the process was sound, and its precondition changed underneath it.**
  The precondition was never written down: "a DHW-blocked plan never builds
  the replan, because the replan fires only on DHW power the block has
  removed". It held at `64a54195`, and `81aa0c3b` made it false.
  - #470's own tests exercise the coil credit on unblocked solves.
  - The v5.3.0 suppression fixture has no wood coil, so it still cannot reach
    the new route.
  - `rca_suite_reach.py` over `tests/features.py` at `754d2319`, the fix
    base, counts blocked solves separately from unblocked ones, with
    pass-through spies:

    | ref | script result | blocked: solves / `_co_optimize` entered / replans built / adopted | unblocked: solves / entered / built / adopted (DHW kWh) |
    |---|---|---|---|
    | `64a54195` | `ALL 1430 FEATURE CHECKS PASSED` | 2 / 2 / 0 / 0 | 90 / 73 / 40 / 1 (6.021) |
    | `754d2319` | `ALL 3597 FEATURE CHECKS PASSED` | 2 / 2 / 0 / 0 | 179 / 102 / 66 / 3 (18.518) |

    Raw lines: `reach_64a54195_features.json`, `reach_754d2319_features.json`.
    A first run at `754d2319` failed 5 cap checks that bind `inspect.signature`
    of `optimize`, which the spy then hid. The spy now carries
    `functools.wraps`, and the counts were the same in both runs.

  The suite built the replan and adopted it under no block. It never built it
  under one. No check could notice that the precondition had moved.

The P2 RCA recorded the same state for one of its instances. D12-s2-02
escaped the #1576 census because the census's stated precondition ("no written
slot accepts `sensor`") changed under it (`tools/audit/rca/R9-P2.md`).

### The fix's own census has the same blind spot

EG-B8 added two checks on the wood_coil fixture at -2.0:
- "a DHW-blocked plan ships no hot water when mostly negative prices tempt the
  co-optimisation replan (#1747)", an output check;
- "and every DHW build that solve made was told the mode is blocked", an
  input census. It spies on `_build_dhw_requirements` and asserts
  `len(args) >= 1 and all(args)`.

The census sees an omitted block whether or not the replan wins, so it is the
stronger of the two. But it does not assert that it saw the replan: it passes
with one build seen. That leaves it open to the same (d) shape. If a later
route builds the replan off the spied callable, as EG-B5's planner call may,
the census stays green.

`rca_census_reach.py` replays its fixture and evaluates both predicates
verbatim. At EG-B8's code head `1b43198e`:

```
arm=as-is     builds_seen=[True, True] shipped_dhw_kwh=0.00 breach=20.810 check_first=pass check_companion=pass companion_with_reach(>=2)=pass
arm=no-replan builds_seen=[True]       shipped_dhw_kwh=0.00 breach=20.810 check_first=pass check_companion=pass companion_with_reach(>=2)=FAIL
arm=off-spy   builds_seen=[True]       shipped_dhw_kwh=9.22 breach=0.629  check_first=FAIL check_companion=pass companion_with_reach(>=2)=FAIL
```

At `754d2319`, the as-is arm reads `[True, False]` and every predicate fails.
So on the route that existed, the census detects the defect.

In `off-spy`, the replan rebuilds through an unspied callable that drops the
block. That is #1747 again on a new route, and the census passes it. The
output check catches it only because this fixture's price shift makes the
replan win.

A reach clause (the replan's build is among the builds seen) fails in both
perturbed arms and passes as-is. It turns the unwritten precondition into an
assertion. That is the (d) countermeasure `defect-root-cause.md` names:
"making the process notice its own precondition change".

### How far the class reaches

**Class P2** (`tools/audit/bugclasses.json`): "One fact decided twice by
divergent predicates: a guard at one seam, missing at its sibling". Here the
guard is the DHW mode block, and the two seams are the two builds of one plan.
- P2 has 66 instances over rounds 1–9, 27 of them in round 9.
- Its status is `open`, with a null detector and a null barrier.
- Its barrier is owned by R9-F1.11 (`rca_planned`).
- #1747 came from the EG-B5 design seats, not from a judged audit finding, so
  it is not in the register. It belongs under `non_round_instances`.

The fixer's draft counted "1 instance of a defaulted keyword omitted at a
second call site". That measures a narrower syntactic sub-shape.

The class search used that sub-shape's instrument, `kwarg_seams.py` (the
fixer's, sha1 `25ec2ea2`), over every `custom_components/heatpump_optimizer/*.py`
(67 files). It reports each `self.<m>(...)` called from two or more sites in
one module where a keyword that `m` defaults is passed at one site and omitted
at another.

|---|---|---|
| `64a54195` (v5.3.0) | 19 | 1 (unreachable at that ref) |
| `754d2319` (fix base) | 63 | 1 |

Disposition of the 62 at the fix's head. This seat read each site, except
where noted.

- **`optimizer.py` (10):** the fixer's dispositions in #1786's body. This seat
  re-read them, and they hold.
  - `space_demand` is omitted at the first build by design.
  - `_build_result`, `_compute_baseline_power`, `_deferred_energy_cost` and
    `_settlement_caps` omit their DHW keywords in the space-only solve, which
    has no DHW store.
- **`coordinator.py` (7):**
  - `_mold_floor_series` without `target_cap` in the live solve, by design.
    Its docstring caps at the configured target, and only what-if solves pass
    one.
  - `_plan_slots` without `reasons` or `other_powers` (4). The what-if
    summary reads only `len()` of the result, and neither keyword changes the
    slot count.
  - `_tibber_fetch_failed` without `exc_info` (2). This is a logging choice.
- **`thermal_model.py` (6):**
  - `_simulate_step_single` without `_cop`, `_q_solar` or `_u_eff` (3). The
    `n_sub == 1` path computes them inside; they are precomputed only for the
    subdivision loop (#1723).
  - `compute_cop` without `flow_temp` (3). The space flow is the default, and
    the buffer store passes its own.
- **`config_flow.py` (39):** `async_show_form` without
  `description_placeholders` (24) or `errors` (15). These are Home Assistant
  framework calls where each form supplies its own. They are dispositioned as
  a group and **were not read one by one**.

The instrument's precision on this tree is 1 defect in 63 seams at the base.
Nothing else it returns is a second instance.

It also cannot see this defect's history. At `64a54195` it reports the seam
while the seam is harmless, and nothing it measures changes at `81aa0c3b`,
where the harm began. A syntactic seam lint cannot tell a latent omission from
a live one. Only a check that drives the route can.

## Cost test

`cost(countermeasure, recurring) < cost(defect) x P(recurrence)`, wall-clock
per round (one audit round and its fix wave).

**cost(defect)**, measured from session and PR timestamps:
- EG-B8 fixer seat: 14:02:34Z to 15:24:28Z, 82 min;
- fix review: 15:28:32Z to 16:07:29Z, 39 min;
- total: **121 min**. PR #1786 was open for 42 min of it (15:26:40Z to
  16:09:09Z).

That figure is not split from the F9.3 carry (the `normalize_profile`
projection), which rode the same PR, so it overstates #1747 alone. It excludes
the mapping, skeptic and review seats that found the defect, and this seat.

**P(recurrence):**
- the class: 66 instances in 9 rounds (mean 7.3 per round), and 27 in round 9
  (`bugclasses.json`);
- the syntactic sub-shape: 1 known instance in 9 rounds. That is an estimate,
  from the absence of any other among the 63 seams above and in the register.

**Option 1: a standalone `kwarg_seams.py` check** (the fixer's candidate).
- Standing cost: 3.2, 3.6 and 3.4 s over three runs across the 67 modules, at
  load average about 2 on 4 cores. At R9-P2.md's assumed 41 PRs × 3 gate runs
  per round, that is 418 s, or about **7.0 min per round**.
- Upkeep: 62 disposition rows at landing, and a new row for every legitimate
  seam after that.
- Benefit, for its sub-shape: 121 min × 1/9 ≈ **13.4 min per round**. That
  passes by 1.9×, on an estimated P, at 1-in-63 precision.
- Against it:
  - it could not have caught #1747 when the harm began (above);
  - it would be a second check guarding a P2 fact outside the P2 registry,
    which R9-P2.md refused ("so that one shape is not guarded by two checks").

**Option 2: a reach clause on EG-B8's census.**
- Standing cost: one comparison in an existing check, **≈ 0**.
- It fails on both routes the census misses today (the `off-spy` and
  `no-replan` arms), and it passes on the fixed tree.

**Verdict.** P2 is an audit class (27 instances in round 9, at least 3), so a
barrier is owed whatever the test says (`defect-root-cause.md`, the
audit-class exception). The test picks its form:
- Option 2, at 0 against 13.4 min per round, landed inside the P2 barrier.
- No standalone check from this seat.
- `kwarg_seams.py` goes to the barrier's owner as a candidate registry shape,
  with its measured precision, not as a gate.

## Countermeasure

This maps to the (d) finding. It makes the check notice when its precondition
moves, instead of giving anyone a firmer instruction.

- **Carried to R9-F1.11, the P2 barrier:** the fourth carry in
  `.claude/workflows/carry-1644.json` (`brief_lint.mjs` labels it `carry 3`).
  - Name EG-B8's census as the P2 registry's holder for this fact.
  - Give it the reach clause, demonstrated as above.
  - Add #1747 to P2's `non_round_instances`.
  - `kwarg_seams.py` is offered as a shape, with the 62 dispositions above.
    Its key must not be able to silence the replan's own call (`fixer.md`
    step 14).
- **Carried to R9-EG-B5**, which turns the replan into a planner call: the
  second carry in `.claude/workflows/carry-1743.json` (`carry 1`).
  - Re-point the spy at the callable the planner uses.
  - Keep the reach clause, so the census refuses rather than passes if it
    loses the replan.
- **Policy: none new.** R9-P2.md has already drafted the clause "a census
  asserts its own preconditions" for `fixer.md` step 8. It waits on tvofi's
  approval under F11.5, and it is the policy-level form of this
  countermeasure. #1747 is a second worked example for that draft: a trigger
  added to a guard by one fix made reachable an omission another feature had
  left harmless.

The roster briefs of R9-F1.11 and R9-EG-B5 on `handoff/audit-r9-fixplan` carry
the same text (`a11bf386`; `finding-propagation.md` requires both copies).
Where the two copies disagree, the newer one is right.
